# チェックリスト：noteすき間判定（003 × 008）

目的：需要はあるが、有料の出し手が少ない切り口かを判定する。  
根拠：`003_noteで稼げるニッチジャンルを見つける方法！` と `008_noteで稼ぐ初心者でも失敗しないジャンル選び…`

使い方：候補テーマを1行で書いてから、上から順に埋める。AIに頼むときは、この表を渡し「候補テーマ」を指定する。

---

## 0. 候補の定義

| 項目 | 記入 |
|------|------|
| 候補テーマ（具体文） | |
| 誰の・どんな状況の悩み／欲求か | |
| 自分が語れる理由（体験／調査速度／専門） | |
| 今日の日付 | |

※「恋愛」「AI」など広い名詞だけは不可。一段具体にする。

---

## 1. 需要の痕跡（003）

| # | 確認項目 | 見る場所 | 記入・メモ | 判定 |
|---|----------|----------|------------|------|
| 1-1 | noteのカテゴリ階層に載るか | note左ナビ：大→中→細 | | 載る / 載らない / 不明 |
| 1-2 | 載る場合、階層パス | 例：くらし > 健康医療 > … | | |
| 1-3 | キーワード検索で関連記事が出るか | note検索 | 件数の体感：多い／普通／少ない | |
| 1-4 | 有料記事があるか | 検索後、有料に絞る | 本数： | あり / なし |
| 1-5 | 支払いの痕跡 | 有料記事のスキ数・「買った」系コメント | | 強い / 弱い / なし |
| 1-6 | note外の需要 | YouTube検索、X、質問サイトなど | | あり / なし |

**この段の結論**

- カテゴリに載る＋支払い痕跡あり → 需要ありとして次へ  
- カテゴリに載らない → 「需要なし」か「語り手不足」の二択。2へ進み、競合の少なさも見てから3で最終判断  

---

## 2. 供給（ライバル）の少なさ（003 × 008）

| # | 確認項目 | 見る場所 | 記入・メモ | 判定 |
|---|----------|----------|------------|------|
| 2-1 | 同じ切り口の有料本数 | note検索（有料） | 本数： | 少ない / 普通 / 多い |
| 2-2 | ハッシュタグ上の発信者 | noteハッシュタグ | 目立つ人： | 少ない / 多い |
| 2-3 | 直接競合 | 同じテーマ・同じ切り口 | 名前・URL： | 0 / 1〜3 / 4以上 |
| 2-4 | 間接競合 | 隣接テーマ・同じ読者層 | 名前・URL： | |
| 2-5 | 潜在競合 | 今は違うが寄りそうな人 | 名前・URL： | |
| 2-6 | 空きの有無 | 競合の見出し・ターゲットを見て、一段深い悩みが空いているか | 空いている切り口： | 空あり / 空なし |

**競合を見るときの固定項目（008）**  
見つかったアカウントごとに、次だけメモする。

- フォロワー数  
- 更新頻度  
- 有料／無料の比率  
- 有料の価格帯  
- 特典・割引の有無  
- SNS集客の有無  
- ターゲットの言い方  
- 人気記事のテーマと見出しの型  
- 文章のトーン  
- 独自性  
- スキ・コメントで褒められている点  

**この段の結論**

- 有料が少なく、支払い痕跡がある → すき間候補（SKY寄り）  
- 有料が多い → 正面衝突しない。2-6の「一段深い切り口」だけ残す（008）  
- 有料がゼロ → 宝か未知数。3へ  

---

## 3. 未知数・宝の最終ゲート（003）

競合がほぼいないときだけ使う。

| # | 質問 | 答え | 判定 |
|---|------|------|------|
| 3-1 | 文字・動画・音声・メンバーシップのどれかで、悩みを前に進められるか | | はい / いいえ |
| 3-2 | 悩み解決ではない場合、読み物として熱が続くか | | はい / いいえ / 対象外 |
| 3-3 | 今すぐ解決したい深さ・緊急度はあるか（人数の多さだけ見ていないか） | | はい / いいえ |

**判定**

- 3-1 か 3-2 のどちらかが「はい」、かつ 3-3 が「はい」→ 試験候補  
- どちらも「いいえ」→ 見送り  

---

## 4. 一段絞り（008）※競合が多いとき必須

広いテーマのまま終わらない。次の型で書き換える。

| 項目 | 記入 |
|------|------|
| 大テーマ | |
| 属性（誰） | |
| 状況（いつ・どんな状態） | |
| 手段・切り口（何をどうするか） | |
| 絞った後の1文 | |

例（008の考え方）：  
「異性と付き合う方法」→「MBTIがINFPのHSPが、相性の良い相手と出会う具体手順」

絞った1文で、もう一度 **1〜2** をやり直す。

## 5. 総合判定

| 選択肢 | 条件の目安 |
|--------|------------|
| A. 試験する | 需要の痕跡あり＋供給が少ない（または一段絞り後に空きあり）＋自分が語れる |

## AIに頼むときの依頼文（コピー用）

```
候補テーマ：〇〇
このチェックリスト（003×008）に沿って、note上を見て表を埋めて。
優先順：カテゴリ痕跡 → 有料の本数とスキ／コメント → 直接競合の有無 → 一段深い空き。
取れない項目は「取得不可」と書き、代わりに手動で見るURLを提示して。
最後に A / B / C で総合判定して。
```

---

## 取得の限界（運用メモ）

- noteの検索・カテゴリは画面側の表示が多く、AIが毎回すべて自動取得できるとは限らない。  
- 取れる：公開記事URL、プロフィール、見出し、スキ数、価格表示、検索結果の一部。  
- 取りにくい：左ナビのカテゴリ階層の完全自動、ログイン限定、急変するランキング全体。  
- 取れない項目は、人がURLを開くか、画面の文言を貼る。

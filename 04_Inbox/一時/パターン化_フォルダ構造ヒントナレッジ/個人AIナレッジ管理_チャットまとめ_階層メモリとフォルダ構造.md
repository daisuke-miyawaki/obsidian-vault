# 個人AIナレッジ管理 チャットまとめ
## 階層型メモリ・OS層・フォルダ構造を中心に

最終更新: 2026-07-31

このドキュメントは、個人専用AIアシスタントのナレッジ管理に関する一連の議論をまとめたものです。  
特に「Core（OS層）」と「実用的なフォルダ構造」を中心に、詳細に補足を加えて整理しています。

---

## 1. 全体の考え方の概要

AIに「長く正しく自分を理解させ続ける」ためには、ただ会話履歴を残すだけでは不十分です。  
**階層型メモリ**の考え方を取り入れ、情報を「時間軸」と「重要度」で分けて管理することが重要です。

### 階層の基本イメージ（パソコンの例え）

| 種類 | パソコンでの例え | AIでの役割 | 消えるタイミング |
|------|------------------|------------|------------------|
| **コア（短期・常時）** | RAM（今すぐ使うメモリ） | 超重要な事実・価値観・ルール・現在の方針 | 会話終了・再起動で基本的にリセット（必要なら長期へ移行） |
| **長期記憶** | ハードディスク | 過去の大事な知識・事実・ファイルの内容 | 自分で消さない限り残る |
| **会話履歴（Recall）** | 最近のログ | 直近のやり取り | 一定期間後に要約または削除 |

- **コア**は「今この瞬間にAIが頭の中で意識している情報」  
- **長期記憶**は「倉庫にしまっておいて、必要なときに取り出す情報」

この分け方を意識することで、コンテキストの無駄な肥大化を防ぎ、AIの応答精度を高く保てます。

## 2. 主要なツールの位置づけ

議論の中で出てきた主なツールと、それぞれの役割です。

### Letta（旧MemGPT）
- **特徴**: LLMを「OSのように扱う」メモリ管理。エージェント自身が記憶を編集・管理する。
- **階層**: Core（常時コンテキスト内） / Recall（会話履歴） / Archival（長期倉庫）
- **向いている用途**: 「あなたを覚え続ける」本格的な個人アシスタント。自己編集メモリが強み。
- **保存形態**: 最近はMemFS（git管理のMarkdownファイル群）もサポート。`system/`フォルダがコアに相当。

### Mem0
- **特徴**: 会話から「覚えておくべき事実」を自動で抜き出して保存する記憶レイヤー。
- **強み**: 自動抽出・重複排除・意味検索。
- **注意点**: 全文を保存するのではなく、整理された短い事実を残す。カテゴリールールを自動で理解して守るわけではなく、メタデータやタグを付けて外側で制御する。
- **位置づけ**: 「情報ナレッジを自動で整理・保管する倉庫番」。

### Cursor / Hermesエージェント
- **特徴**: ファイル操作やテンプレート適用が得意。
- **向いている用途**: インボックスに溜まった事実を、後から一括でテンプレート・YAML・MOCに沿って綺麗なノートに整える作業。

**役割分担のイメージ**  
- 会話中の事実抽出 → Mem0  
- リアルタイムの記憶管理・自己整理 → Letta  
- 後処理で綺麗なノートに整える → Cursor / Python

## 3. あなたに特に合うフォルダ構造（詳細・補足付き）

議論の結果、**実用派の構造**があなたの現在の運用に最も近いと判断されました。  
以下に、推奨されるトップレベル構造を詳細にまとめます。

```
00_System / 00_Core     ← ルール・価値観・OS層（ここが最重要）
01_Inbox / インポート   ← とりあえず入れる場所
02_Projects / 活動基盤  ← 進行中のプロジェクトや活動
03_Resources / 素材庫   ← 参考資料・知識の材料
04_Areas / アイデア     ← 継続的なテーマやアイデア
05_Archive / アーカイブ ← 終わったもの
99_Attachments          ← 画像やファイル
```

### 各フォルダの役割と補足説明

#### 00_System / 00_Core（最重要）
**役割**: AIが「常に守るべき土台」を置く場所。OS層に相当します。

ここに入れるもの例：
- 自分の目的・ビジョン
- AIと協力する意味・役割分担
- 価値観・性格・特徴
- 全体の運用ルール
- AI活用のルール（どのように振る舞ってほしいか）
- テンプレートやYAMLの基準
- Pure_OS_Town的な厳格なルール（何をコアに残すか、純度を保つ基準など）

**補足**:
- ここが「コア」です。毎回のチャットで必ず（またはほぼ必ず）読み込ませる部分。
- 容量が限られるため、「本当に常時必要なものだけ」に絞ることが大切。
- チャットの種類によって「この中の一部だけを追加で読む」という制御をすると、さらに精度が上がります。
- Lettaを使う場合は、MemFSの`system/`フォルダに相当する位置づけになります。

#### 01_Inbox / インポート
**役割**: とりあえず何でも入れる「入り口」。

- 会議の文字起こし
- 思いつきのメモ
- 外部から取り込んだ資料
- Mem0が自動抽出した事実の一時置き場

**補足**:
- ここは「整理前」の場所です。溜めすぎないように、定期的に処理する習慣を作るのがポイント。
- LLM Wikiで言う`raw/`に近い役割。
- 後からCursorなどで一括処理して、適切なフォルダへ振り分ける運用と相性が良い。

#### 02_Projects / 活動基盤
**役割**: 進行中のプロジェクトや、明確な成果・期限がある活動。

- 個別のプロジェクトフォルダを中に作るのが一般的。
- 例: クライアント案件、新サービス開発、特定のキャンペーンなど。

**補足**:
- 「終わったら05_Archiveへ移す」というルールを決めておくと、常に「今動いているもの」だけがここにある状態を保てます。
- チャットの種類が「プロジェクトA」の場合は、この中の該当プロジェクト情報を追加で読み込ませる。

#### 03_Resources / 素材庫
**役割**: 参考資料・知識の材料・再利用可能な情報。

- 業界知識
- マーケティングの型
- 過去の成功事例
- 技術的なメモ
- 書籍や記事の要約など

**補足**:
- 「今すぐ使わないが、後で役立つ可能性が高いもの」を置く場所。
- LLMに「この素材を基にwiki的な整理をして」と指示する対象にもなる。

#### 04_Areas / アイデア
**役割**: 継続的なテーマや、期限のないアイデア・関心領域。

- 長期的に育てたいテーマ
- アイデアの種
- 個人的な探求テーマ
- 日記や振り返りに近いもの

**補足**:
- Projects（期限あり）とAreas（継続的）を分けることで、頭の中が整理されやすくなります。
- ここがあなたの「05_アイデア」に相当する部分。

#### 05_Archive / アーカイブ
**役割**: 終わったもの・使わなくなったものを移す場所。

- 完了したプロジェクト
- 古くなった情報
- 参考に残しておきたいが、日常的には見ないもの

**補足**:
- 削除するのではなく「アーカイブする」ことで、後から必要になったときに探せます。
- 定期的に「本当に必要か」を見直すと、さらに綺麗に保てます。

#### 99_Attachments
**役割**: 画像、PDF、その他の添付ファイルをまとめて置く場所。

**補足**:
- Markdownノートからリンクで参照する形が一般的。
- ファイル名を分かりやすくしておくと、後で探しやすいです。

## 4. 運用のポイント（あなたに特に合う部分）

### チャットの内容によって読み込むものを変える
Coreに情報が多くなっても、毎回全部を読み込ませる必要はありません。

**推奨パターン**:
1. **共通で必ず読むもの**（最低限の価値観・基本ルール）
2. **チャットの種類に応じて追加で読むもの**
   - プロジェクト相談 → 該当プロジェクト情報
   - マーケティング → 関連ルール・素材
   - お客さん対応 → お客さん関連情報
   - 個人的な振り返り → 深い価値観や日記的なもの

スタート時に「今回は〇〇用のセットを読んで」と指定するだけでも効果があります。  
慣れてきたら、AI側に「チャットの最初の内容を見て、適切なセットを選んで」と任せる半自動化も可能です。

### 自動化の進め方（現実的な順番）
1. まずCore（OS層）を固める（すでにかなりできている状態）
2. 情報ナレッジを大まかなカテゴリーで分ける
3. Inboxに溜まったものを、定期的にCursorやPythonで一括処理する
4. ルールを最初のプロンプトやルールファイルに書いて、LLMに守らせる比重を徐々に上げる
5. 必要に応じてMem0を足して、事実抽出を自動化する

「最初から全部自動」ではなく、「ルールを人間が決めて → LLMにそのルールで作業させる」形が、コントロールと楽さのバランスが良いです。

### LLM Wikiとの関係
あなたがやろうとしていることは、広い意味で「Wiki的なナレッジ管理」です。  
欧米のLLM Wiki（Karpathy流）が「LLMに知識の本体を書かせる比重が高い」のに対し、  
あなたのやり方は「人間がルール（テンプレート・YAML・MOC）を細かく決めて、そのルールに沿って整える」よりコントロールが強いバージョンです。

両方の良いところを取り入れられます。

---

## 5. まとめ

- 階層型メモリ（コアと長期）を意識することが、個人AIを長く使う上での基盤になる。
- フォルダ構造は「00_Coreを最上位に置く実用派」が、あなたの現在の運用に最も合っている。
- Coreにルールや自分の情報を厚く入れつつ、「チャットの種類で読み込むものを変える」運用が有効。
- 自動化は「ルールを最初に決めて、LLMに守らせる」形で進めると現実的。
- Mem0は「事実の自動抽出」、Lettaは「自己管理する記憶」、Cursorは「後処理での綺麗な整理」と役割を分けると使いやすい。

このまとめが、今後のナレッジ管理の設計・改善のベースになれば幸いです。

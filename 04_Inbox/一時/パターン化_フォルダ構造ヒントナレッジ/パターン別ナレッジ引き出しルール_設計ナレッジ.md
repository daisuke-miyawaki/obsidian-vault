# パターン別ナレッジ引き出しルール 設計ナレッジ

最終更新: 2026-08-01

このドキュメントは「プロンプト」ではなく、**ナレッジ**として読み込ませるためのものです。  
パターン別の引き出しルールを設計する際の前提知識・考え方・進め方をまとめています。

---

## 1. このナレッジの目的

チャットの目的や状況に応じて、ナレッジベース全体から必要な情報を過不足なく引き出すための「パターン別ルール」を設計するための基礎知識です。

Coreだけを読むことは稀です。  
多くの場合、以下を組み合わせます：

- 共通Coreの一部
- 用途に応じたCoreの一部
- 関連するProjects情報
- 関連するResources（素材・知識）
- 関連するAreas（アイデア・テーマ）
- 必要に応じてお客様情報やArchive

「どの状況のときに、どのナレッジから何を優先して引き出すか」をパターンとして定義することが目標です。

---

## 2. 前提となるフォルダ構造

```
00_Core / 00_System     ← ルール・価値観・OS層（最重要）
01_Inbox / インポート   ← 未整理（基本的に読まない）
02_Projects / 活動基盤  ← 進行中のプロジェクト
03_Resources / 素材庫   ← 参考資料・知識の材料
04_Areas / アイデア     ← 継続的なテーマやアイデア
05_Archive / アーカイブ ← 終わったもの
99_Attachments          ← 画像やファイル
```

---

## 3. パターン設計の基本考え方

### パターンとは
よくあるチャットの種類・状況を分類したものです。  
例：
- お客さん案件の相談
- 特定プロジェクトの進行・深掘り
- マーケティング施策の検討
- アイデア出し・発想
- 全体方針の相談
- 振り返り・自己理解
- など

それぞれに「Aパターン」「Bパターン」などの名前（または分かりやすい名前）をつけ、  
「このパターンのときはこれとこれを読む」というルールを定義します。

### 設計時の原則
- Coreだけに偏らない
- 関連度の高い情報を優先する
- 読み込みすぎてコンテキストが薄まらないようにする
- 必要十分のバランスを取る
- 後から見直して改善できるように、明確に書いておく

---

## 4. パターン定義の進め方（推奨ステップ）

1. **よくあるチャットの種類・状況を洗い出す**  
   実際に自分がよく使う場面をリストアップする。

2. **パターンに名前をつける**  
   A・B・C… でも良いし、「顧客案件パターン」「プロジェクト深掘りパターン」などの名前でも良い。

3. **各パターンごとに引き出し内容を定義する**  
   - どのフォルダから読むか
   - Coreのどの部分を含めるか
   - 優先順位
   - 特に注意する点

4. **表形式や箇条書きで再利用可能な形にまとめる**  
   後からすぐ参照できるようにする。

5. **運用しながら改善する**  
   実際に使ってみて「このパターンが足りない」「この組み合わせが良い」と調整する。

---

## 5. パターン定義の出力イメージ

最終的に以下のような形でまとまっていると使いやすいです。

### パターン一覧
| パターン名 | 使う状況の概要 |
|-----------|----------------|
| Aパターン | 〇〇のとき |
| Bパターン | 〇〇のとき |
| Cパターン | 〇〇のとき |

### 各パターンの詳細例
**Aパターン（顧客案件パターン）**
- 使う状況：お客さんに関する相談・提案・対応
- 読み込む優先順位：
  1. 共通Coreセット
  2. お客さん対応用Coreセット
  3. 該当お客さんの情報
  4. 関連するProjects
  5. 関連するResources
- 注意点：〇〇

（同様にBパターン、Cパターン…を定義）

---

## 6. 注意点・補足

- Inboxの未整理情報は基本的に直接読み込まない。
- Archiveは「過去の参考が特に必要な場合のみ」読む。
- パターンは最初から完璧に作ろうとせず、主要なものから順に定義していく。
- このナレッジは「ルールを作るための考え方」であり、完成したルールそのものではない。  
  実際のパターン定義は、このナレッジを読み込んだ上で対話形式で作成する。

---

このナレッジを、他の関連ナレッジと一緒に読み込ませた上で、パターン別ルールの設計を進めてください。

# パターン別ナレッジ引き出しルール作成プロンプト

このプロンプトは、**別のチャットで使うためのものです**。  
目的は「チャットの種類・状況に応じて、どのナレッジから何を引き出すか」を、Aパターン・Bパターン・Cパターンなどの形で体系的に定義することです。

このチャットでは、以下の2つのナレッジも一緒に読み込ませてください：
- ナレッジ読み込みルール_全体構造とセット定義.md
- 個人AIナレッジ管理_チャットまとめ_階層メモリとフォルダ構造.md

（必要に応じて他のCore情報や既存のルールも追加で渡してください）

---

## プロンプト本文（これをコピーして使う）

```
あなたは「個人AIのナレッジ引き出しルール設計の専門家」です。

私は、チャットの目的や状況に応じて、自分のナレッジベース全体から必要な情報を過不足なく引き出すための「パターン別ルール」を作りたいと考えています。

### 前提となるナレッジ構造
私のナレッジは以下のフォルダで管理されています：

00_Core / 00_System     ← ルール・価値観・OS層（最重要）
01_Inbox / インポート   ← 未整理（基本的に読まない）
02_Projects / 活動基盤  ← 進行中のプロジェクト
03_Resources / 素材庫   ← 参考資料・知識の材料
04_Areas / アイデア     ← 継続的なテーマやアイデア
05_Archive / アーカイブ ← 終わったもの
99_Attachments          ← 画像やファイル

Coreだけを読むことは稀です。ほとんどの場合、Coreの一部 + Projects + Resources + Areas などを組み合わせて読みます。

すでに「ナレッジ読み込みルール_全体構造とセット定義.md」と「個人AIナレッジ管理_チャットまとめ_階層メモリとフォルダ構造.md」を渡しています。これらを前提知識として使ってください。

### あなたの役割
私と対話しながら、以下を一緒に作り上げてください。

1. **よくあるチャットの種類・状況を洗い出す**
   - 例：お客さん案件の相談、特定プロジェクトの進行、マーケティング施策検討、アイデア出し、全体方針の相談、振り返り・自己理解 など
   - 私の実際の使い方に合わせて、具体的なパターンをリストアップする

2. **各パターンに名前をつける**
   - Aパターン、Bパターン、Cパターン… または、より分かりやすい名前（例：顧客案件パターン、プロジェクト深掘りパターン など）

3. **各パターンごとに「何を引き出すか」のルールを明確に定義する**
   - どのフォルダから
   - どの程度の範囲・深さで
   - 優先順位はどうするか
   - Coreのどの部分を含めるか
   を具体的に決める

4. **ルールを再利用可能な形でまとめる**
   - 後から見返してすぐ使えるように、表形式や箇条書きで整理する
   - 「このパターンのときは、これとこれとこれを読む」が明確に分かるようにする

### 進め方のルール
- 一度に全部を決めようとせず、ステップバイステップで進めてください
- 最初に「よくあるチャットの種類を一緒に洗い出しましょう」から始めてください
- 私が答えやすいように、具体例を出しながら質問してください
- ルールが複雑になりすぎないよう、必要十分のバランスを意識してください
- 途中で「この定義で良いですか？」「もっと細かくしますか？」と確認を入れてください
- 最終的に「パターン一覧表」と「各パターンの詳細ルール」を出力してください

### 出力のイメージ（最終的にこうなってほしい）
- パターン一覧（名前と簡単な説明）
- 各パターンの詳細：
  - このパターンを使う状況
  - 読み込むナレッジの優先順位付きリスト
  - 特に注意する点
- 必要に応じて「例外パターン」や「組み合わせパターン」も検討する

まずは、私のナレッジ構造と渡した2つのファイルを踏まえて、
「よくあるチャットの種類・状況を洗い出す」ところから始めてください。
私が答えやすいように、質問形式で進めてください。
```

---

## 使い方

1. 新しいチャットを開く
2. 先に以下の2つのファイルの内容を渡す（または添付する）
   - ナレッジ読み込みルール_全体構造とセット定義.md
   - 個人AIナレッジ管理_チャットまとめ_階層メモリとフォルダ構造.md
3. 上記の「プロンプト本文」を貼り付ける
4. AIが「よくあるチャットの種類を洗い出しましょう」と聞いてくるので、対話形式で進める
5. 一緒にAパターン・Bパターン…を定義していく

このプロンプトは、ルールを「作る過程」を重視して設計しています。  
一度に完成させようとせず、対話しながら精度を上げていく形です。

必要に応じて、プロンプトの調整も可能です。

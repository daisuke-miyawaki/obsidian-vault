# ナレッジ読み込みルール
## 全体構造とセット定義（Core + 全体ナレッジ）

最終更新: 2026-07-31

このドキュメントは、「チャットの種類に応じて、Coreだけでなく全体のナレッジから必要なものを組み合わせて読み込む」ためのルールと定義です。  
別チャットで使うプロンプトの前提知識として使ってください。

---

## 1. 基本方針

- **Coreだけを読むことは稀**である。
- ほとんどのチャットでは「共通Core + 用途別Core + 関連するProjects / Resources / Areas の情報」を組み合わせる。
- 目的は「必要な文脈を過不足なく渡す」こと。全部を読み込むのではなく、**関連度の高いものを選んで読む**。

### 読み込みの優先順位
1. 共通Coreセット（ほぼ必須）
2. 用途別Coreセット（チャットの種類に応じて）
3. 関連するProjects情報
4. 関連するResources（素材・知識）
5. 関連するAreas / アイデア
6. 必要に応じてArchiveやAttachments

---

## 2. フォルダ構造の再確認（読み込み対象）

```
00_Core / 00_System     ← OS層（ルール・価値観・自分の情報）
01_Inbox / インポート   ← 未整理（基本的に読み込まない。処理後に移動）
02_Projects / 活動基盤  ← 進行中のプロジェクト
03_Resources / 素材庫   ← 参考資料・知識の材料
04_Areas / アイデア     ← 継続的なテーマ・アイデア
05_Archive / アーカイブ ← 終わったもの（必要な場合のみ）
99_Attachments          ← 画像・ファイル
```

---

## 3. セットの定義

### 3.1 共通Coreセット（ほぼ毎回読む）
- 自分の基本的な目的・ビジョン
- AIとの協力ルール・役割分担
- 基本的な価値観・性格・特徴
- 全体の運用ルール（ナレッジの扱い方など）
- 最低限の「私はこういう人間です」という情報

→ これが「土台」。外すことはほとんどない。

### 3.2 用途別Coreセット（チャットの種類で追加）
用途に応じて、Coreの中から追加で読むセットを定義する。

例：
- **プロジェクト用セット**: プロジェクト進行のルール、意思決定の基準、優先順位の付け方など
- **お客さん対応セット**: お客さんとの接し方、コミュニケーションの原則、注意点など
- **マーケティング用セット**: マーケティングに関する自分の方針・ルール
- **個人振り返りセット**: 深い価値観、日記的な自己理解、長期的な成長の視点など
- **アイデア発想セット**: 発想のルール、制約の外し方など

※ 実際のセット名と中身は、すでにあるCoreの内容に合わせて調整する。

### 3.3 全体ナレッジからの追加読み込み
用途に応じて、Core以外からも読む。

| チャットの種類       | 追加で読む主なもの                          |
|----------------------|-----------------------------------------------|
| お客さん・案件の仕事 | 該当お客さんの情報 + 関連プロジェクト + 周辺知識 |
| 特定プロジェクト     | そのプロジェクトフォルダ全体 or 主要ファイル   |
| マーケティング       | 関連Resources + 過去の事例 + 方針              |
| アイデア出し         | Areas / アイデア + 関連Resources               |
| 全体方針の相談       | 共通Coreを厚めに + 必要に応じてProjects概要    |
| 振り返り・自己理解   | 個人振り返りセット + 日記的なAreas             |

---

## 4. 読み込み判断の流れ（推奨）

1. チャットの目的・種類を特定する（お客さん仕事 / プロジェクト / マーケ / アイデア / 振り返り など）
2. 共通Coreセットを必ず含める
3. 用途別Coreセットを追加する
4. 関連するProjects / Resources / Areas を特定して追加する
5. 必要以上に広げすぎない（関連度の高いものに絞る）
6. 読み込むリストを明示してから、本編の会話を始める

---

## 5. 注意点

- Inbox（01）の未整理情報は、基本的に直接読み込まない。整理されてから対象にする。
- Archiveは「過去の参考が必要なときだけ」読む。
- 読み込みすぎるとコンテキストが薄まるので、「今回の目的に直結するもの」を優先する。
- セットの定義は固定せず、運用しながら「このセットが足りない」「この分け方が良い」と改善していく。

---

## 6. このルールの使い方

- 別チャットで「ナレッジ読み込み担当」や「チャット開始時の準備」としてこのルールを渡す。
- 実際の読み込みリストを出力させてから、本編のAIに渡す。
- 徐々に「チャットの最初の一文を見て、自動でセットを提案する」形に進化させる。

このルールを前提に、プロンプトを設計してください。

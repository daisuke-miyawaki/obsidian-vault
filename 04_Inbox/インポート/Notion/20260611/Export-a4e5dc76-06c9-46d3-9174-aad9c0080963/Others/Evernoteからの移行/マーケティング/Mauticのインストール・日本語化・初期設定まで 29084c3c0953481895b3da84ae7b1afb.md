# Mauticのインストール・日本語化・初期設定まで

無料のオープンソースで提供されているMA(マーケティングオートメーション)ツール、Mautic(マウティック)のインストール・日本語化・設定までを詳しく解説していく。と言ってもそれ自体は至って簡単。

高機能で効果がありそうだが高額であるために敷居が高いとうイメージがあったMA。それがオープンソースで無料提供されているのだからつかわない理由がない。

![](Mautic%E3%81%AE%E3%82%A4%E3%83%B3%E3%82%B9%E3%83%88%E3%83%BC%E3%83%AB%E3%83%BB%E6%97%A5%E6%9C%AC%E8%AA%9E%E5%8C%96%E3%83%BB%E5%88%9D%E6%9C%9F%E8%A8%AD%E5%AE%9A%E3%81%BE%E3%81%A7/ambit_300-250.jpg)

### 無料MAツールMauticのインストール(オンプレミス型)

Mauticは、自社の管理するサーバーやレンタルサーバーにインストールして運用するプログラムで提供されているものと、クラウド型で提供されているものとの2種類がある。

クラウドで利用する場合の無料範囲には一定の条件がつけられている。

自社で管理ができるサーバーがあるのであればインストールして使うオンプレミス型で使うことをお勧めする。なぜならインストール自体はとても簡単だからだ。

もちろんデータベースを使うシステムなので、それが利用可能なサーバーが必要となるが、ほとんどの場合は問題ないだろう。

さらにサーバーの機能であるCRONが使えることが条件となる。

CRONとは、設定したタイミングで設定したプログラムを実行するサーバー側の機能だ。初心者が迷うとしたらCRONの設定部分かもしれない。

### サーバー側でMauticが使うデータベースを用意する

Mauticはデータベースを使うPHPシステムだ。

事前準備としてサーバー側でMauticが使うデータベースを用意しよう。

データベース名と、それを使うユーザー名の登録でそれは出来上がる。データを入れる箱と考えて欲しい。

下画像はXserverのデータベースの設定箇所になる。

### Mauticのダウンロード

Mauticをダウンロードしよう。

[Mautic日本語公式ページ](https://jp.mautic.org/)

クラウド型で使う場合は、上記サイトの「デモ」ページからのフリーアカウント申請となる。

ダウンロードが完了したらそれを解凍し、フォルダー名を「mautic」などに変更、サーバーにアップロードする。

アップロードが完了したら

```
https://mydomain.jp/mautic/
```

にアクセスしてみよう。

データベースがMySQLの場合、デフォルトのポート番号は3306となる。

### Databese Name

Database Nameは先ほどサーバーで準備したデータベース名をセットする。

### Databese Table Prefix

こちらはテーブル名の前にMautic専用の接頭辞をつける。もちろん任意の文字列で構わない。

例) ma_

こちらも先ほどサーバーで準備したデータベースのユーザー名をセットする。

### Databese Password

こちらも先ほどサーバーで準備したデータベースのパスワードをセットする。

### Prefix for backup tables

こちらは、先ほどのデータベーステーブルプレフィックスと同じにならないようすれば良い。デフォルトでは「bak_」となっているのでそのままで構わない。

### Mauticが日本語にならない場合の手順

「Apply」で日本語を適用すると「更新が成功しました」という意味の文字が読み取れるが、日本語に変更されていない場合がある。

これは、Mauticのキャッシュ機能が原因の場合がある。

では、キャッシュを削除してみよう。

### キャッシュデータの削除

Mauticの右上にログインしたあなたの名前がある。そこから一旦ログアウトしてブラウザーを閉じる。

FTPクライアントでMauticをインストールしたフォルダーにアクセスする。

Mauticをインストールしたフォルダーの中に入るとappというフォルダーが見えるだろう。

appフォルダーの中にcacheフォルダーがあり、さらにその中にprodというフォルダーがある。このprodがキャッシュフォルダーになる。

Mautic > app > prod

このprodフォルダーをprod_oldなどにリネームする。

※ 下画像はFileZillaというFTPクライアンでアクセスしたものだ。

キャッシュフォルダーなので削除してしまっても構わないが、ここは念のため。

### Mauticのタスクを実行するためのCron設定

Cronとは、指定したタイミングで設定したプログラムを実行するためのサーバー側の機能だ。

Mauticでは、サーバーのCronをつかってタスクを実行させる必要がある。

共有サーバーでも、そのほとんどでCronの追加設定は可能だろう。

ホスティング会社によってその設定方法は違うのだろうが、やるべきことはもちろん同じだ。

ここではXserverでのCron追加方法を紹介する。

必要な情報はPHPのコマンドパス情報と、Mauticのタスクを実行するプログラムのパスになる。

### XserverのPHPコマンドパス情報

Xserverの場合、コマンドパスの情報はサーバー情報の中にある。サーバー情報画面に入り、コマンドパス一覧タブを開く。すると下のような画面で確認することができる。

[](Mautic%E3%81%AE%E3%82%A4%E3%83%B3%E3%82%B9%E3%83%88%E3%83%BC%E3%83%AB%E3%83%BB%E6%97%A5%E6%9C%AC%E8%AA%9E%E5%8C%96%E3%83%BB%E5%88%9D%E6%9C%9F%E8%A8%AD%E5%AE%9A%E3%81%BE%E3%81%A7/untitled%2012)

MauticはPHP言語でのプログラムなのでPHPのパスを使う。サーバー経由で実行するCGIとコマンドラインから実行するCLIの両方で提供されているが、どちらでも動作は可能だ。

ちなみに当サイトではコマンドライン上での実行が可能なCLI版を利用している。

つまり、PHP7.1のCLIパスは、

```
/usr/bin/php7.1
```

ということになる。

### Mauticのタスクプログラムまでのパス

次に、Mauticでタスクを実行するためのパスを調べる。

これもXserverの場合は

```
/home/サーバーID/独自ドメイン名/public_html/
```

が公開フォルダーまでのパスになるため、今回の場合はpublic_html/mauticと、mauticフォルダーまでのパスを控えておく。

### Mauticのcron jobの追加設定

Cronは、どのタイミングでどのプログラムを実行するのかを追加することにより動作するサーバーの機能であることは先に紹介した。

つまり、実行する時間と実行するプログラムをセットすることになる。

Xserverの場合はサーバーパネルの中の「cron設定」内での作業となる。

[](Mautic%E3%81%AE%E3%82%A4%E3%83%B3%E3%82%B9%E3%83%88%E3%83%BC%E3%83%AB%E3%83%BB%E6%97%A5%E6%9C%AC%E8%AA%9E%E5%8C%96%E3%83%BB%E5%88%9D%E6%9C%9F%E8%A8%AD%E5%AE%9A%E3%81%BE%E3%81%A7/untitled%2013)

Cron設定内のCRONタブで時間と実行コマンドを追加する。

以下の3つのジョブはMauticを動作させるために必須となる。

### セグメントを最新に保つジョブ追加

セグメントを最新状態に保つためのジョブを登録する。デフォルトではコンタクトを300件一括処理するようになっている。

下画像はXserverで「10分ごとにプログラムを実行する」ようにセットした例だ。

分のフォームに10を入力。時間、日、月、曜日には*(アスタリスク)を入れる。

コマンドに入れるパスはあなたのサーバー環境のパスを入れる。

[](Mautic%E3%81%AE%E3%82%A4%E3%83%B3%E3%82%B9%E3%83%88%E3%83%BC%E3%83%AB%E3%83%BB%E6%97%A5%E6%9C%AC%E8%AA%9E%E5%8C%96%E3%83%BB%E5%88%9D%E6%9C%9F%E8%A8%AD%E5%AE%9A%E3%81%BE%E3%81%A7/untitled%2014)

セグメントジョブは、

```
php /path/to/mautic/app/console mautic:segments:update
```

となる。

php部分には、先ほどサーバー情報で確認したPHPのコマンドパスにする。

半角スペースを入れて、/path/to/をあなたが利用しているサーバーのパスを入れ、その後にmauticが実行するジョブまでのパスを記載する。

つまり、今回のXserverの例では、

```
/usr/bin/php7.1 /home/サーバーID/独自ドメイン名/public_html/mautic/app/console mautic:segments:update
```

が実際のコマンドになる。

Xserverでは最後にコメントを入れるフォームがあるが、そこにはあなたがあとから見てもわかる説明を入れておけばいいだろう。

### キャンペーンを最新に保つジョブ追加

適用するコンタクトとともにキャンペーンを最新の状態に保つためのジョブを登録する。

方法は先のセグメントのときと同じだ。

ただ、当サイトでは先ほどの10分を11分にして登録した。共有サーバーの場合、その負荷を考えるとCronの実行タイミングをずらした方が良い。

コマンドは、

```
php /path/to/mautic/app/console mautic:campaigns:rebuild
```

となる。

もちろん、phpと/path/to/はあなたの環境に合わせてセットする。

### キャンペーンを実行するためのジョブ追加

Mauticスクリプトがバッチ処理するイベント数はデフォルトで100と設定されている。

追加方法は先ほどと同じになる。

ただ、当サイトでは12分ごとに実行するようにセットした。

コマンドは、

```
php /path/to/mautic/app/console mautic:campaigns:trigger
```

となる。

あなたのサーバー環境に合わせてセットする。

### IP Lookupサービスデータのダウンロード

IP LookupサービスのデータをダウンロードしてMauticにセットする。

といってもそのボタンをクリックするだけで完了する。

ライセンスの問題でMauticに同梱することができないらしい。

設定場所はダッシュボードの右上の歯車のアイコンをクリック。

設定メニューの中に「その他の設定」という項目がある。

IPルックアップサービスはデフォルトでは、「MaxMind – GeoLite2 City Download」になっている。

Mauticsでもこちらを推奨しているようなので特に理由がない限りこれを変更する必要はない。

「取得IPルックアップデータストア」ボタンをクリックする。

[](Mautic%E3%81%AE%E3%82%A4%E3%83%B3%E3%82%B9%E3%83%88%E3%83%BC%E3%83%AB%E3%83%BB%E6%97%A5%E6%9C%AC%E8%AA%9E%E5%8C%96%E3%83%BB%E5%88%9D%E6%9C%9F%E8%A8%AD%E5%AE%9A%E3%81%BE%E3%81%A7/untitled%2015)

しばらくすると「成功」の文字が現れる。

こちらもあっけなく完了となる。

[](Mautic%E3%81%AE%E3%82%A4%E3%83%B3%E3%82%B9%E3%83%88%E3%83%BC%E3%83%AB%E3%83%BB%E6%97%A5%E6%9C%AC%E8%AA%9E%E5%8C%96%E3%83%BB%E5%88%9D%E6%9C%9F%E8%A8%AD%E5%AE%9A%E3%81%BE%E3%81%A7/untitled%2016)

以上でMauticのインストールから日本語化、初期設定が完了となる。

この記事の通りに進めていけば問題なくセッティングまで終了できるだろう。

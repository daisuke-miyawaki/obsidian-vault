# 隠れAI秘書システム（Cushion AI Agent System）構築構想書

## 1. システム概要と開発の背景
本プロジェクトは、ADHDやグレーゾーンの特性（メンタルが繊細、被害者意識・負い目を感じやすい、タスクやNotionの確認を忘れる・脳が拒否する）を持つクライアントと、開発者（宮脇大輔氏）との間のコミュニケーション摩擦をゼロにし、業務を円滑に遂行するための自律型AIサポートシステムである。

クライアントにはシステムやAIの存在を意識させず、すでに心理的依存と高い信頼を寄せている「チャット（LINE）」を唯一のインターフェースとし、裏側でCursor（自律型プログラム）とDify（キャラクター・窓口担当）が連携してクライアントを優しくエスコートする。

---

## 2. システムの全体構造と役割分担
本システムは「頭脳（ロジック処理）」「顔（窓口・キャラ付け）」「ユーザー画面」を完全に分離し、APIコストの最小化と運用の安定性を両立する。

```
【あなた（宮脇氏）】
     │  (Notion / 専用UIからストレートな指示・スケジュール・メールを入力)
     ▼
【頭脳：Cursor（VPS上の自律型Pythonプログラムなど）】
     │  ① メールの自動仕分け・判断（タスク化 / 予定化 / 無視）
     │  ② タスクの超スモールステップ化（ADHD向け細分化）
     │  ③ 費用発生の厳密なコントロール
     ▼（Webhook通信：彼に伝えるべきセリフ台本のみを伝送）
【顔・クッション：Dify（キャラクターチャット窓口）】
     │  ① キャラクター（例：ペン太等）の口調・魂の吹き込み（プロンプト管理）
     │  ② 日常の膨大な雑談や愚痴の100%肯定・メンタルケア（超格安AIモデル）
     ▼
【ユーザー画面：LINE公式アカウント（キャラクター秘書）】
     │  (クライアントが普段からストレスなく開ける唯一の場所)
     ▼
【クライアント（彼）】
```

### 各コンポーネントの詳細役割

#### 1. ユーザーインターフェース：LINE公式アカウント（キャラクター秘書）
* **見た目:** クライアントが親しみを持てるキャラクター（例：執事、動物キャラクター、健気な秘書など）のアイコンと名前。
* **役割:** クライアントからの相談・雑談の受取口であり、タスクの提示・完了報告の窓口。
* **心理的効果:** 「宮脇さんからの直接の指示」というプレッシャーを排除し、「キャラに褒められたいからやる」というポジティブな行動動機へ変換する。

#### 2. フロントレイヤー（顔）：Dify
* **役割:** LINEと1ボタンでAPI連携し、キャラクターの「人格（プロンプト）」を管理する。
* **雑談処理:** クライアントからの「業務に関係のない愚痴や相談」を格安AI（Gemini 1.5 Flash等）で処理し、100%肯定して寄り添う。
* **フィルタリング:** 複雑なロジックは持たせず、クライアントからの「タスク完了報告」や「スケジュール了解」のトリガーを奥のCursorへ中継するのみとする。

#### 3. バックエンドレイヤー（頭脳）：Cursor（VPS上のプログラム）
* **役割:** システム全体の司令塔。メールの自動巡回、Notionデータベースの監視、Googleカレンダー等のスケジュール連携を行う。
* **タスク細分化:** 宮脇氏からの無骨な指示（例：「〇〇修正、明日まで」）を検知し、ADHDの特性に合わせて「脳に拒否反応を起こさせない超具体的な1ステップずつのチェックリスト」に分解する。
* **コスト管理:** AIを呼び出す必要のない処理（プログラムによる条件分岐やデータ転送）を完全に0円で処理し、API通信費を極限まで削る。

## 3. 本アイディアの優れた点（メリット）

* **クライアントの脳の拒否反応を完全回避**
    Notionをいちいち開いて確認する行為を「脳が拒否する」特性に対し、本人が進んで開く「LINEのキャラクターチャット」だけで完結するため、確認漏れや未実行が起きない。
* **被害者意識を刺激しない「クッション効果」**
    宮脇氏のストレートな修正指示や注意が、キャラクターの優しい口調（「〜だペン！」等）や絵文字・スタンプ、そして「宮脇さんがね、〇〇さんのことすごく褒めてたよ！」という三人称の演出に翻訳されるため、攻撃されているという誤解を生まない。
* **ADHDでも健常者のように振る舞える環境の自動生成**
    AIがタスクを「声に出して3回読む」「保存ボタンをポチッと押す」といった極小の行動（スモールステップ）に分解して提示するため、ワーキングメモリが小さくてもミスなく業務を完了させられる。
* **API通信費用（コスト）の最小化**
    「重い処理・プログラム処理」はVPS（Cursor）側の0円ロジックで行い、日々の大量の雑談はDify側で超格安AI（Gemini 1.5 Flash等）に任せることで、月額数百円レベルの圧倒的ローコスト運用が可能。
* **開発とメンテナンスの容易さ**
    Dify側で複雑なワークフローを組むとスパゲッティ化してバグの温床になるが、Difyを「ただのチャット窓口」に割り切ることで、仕様変更（プロンプトの調整やロジック変更）はCursorのコードや指示書をサクッと書き換えるだけで完結する。

## 4. 想定される問題点と対策（リスク管理）

### 問題点1：優しさによる「重要性・締切」の形骸化
* **リスク:** 言葉遣いをマイルドにしすぎたり、キャラクター化したりすることで、クライアントが「やらなくても怒られない」「重要ではない」と誤解し、締切を守らなくなる。
* **対策:** Cursor側のプロンプト（指示書）に「言葉遣いは極限まで優しく寄り添うが、何をいつまでにやるかという事実とタスクの重要性は明確に維持すること」を絶対ルールとして仕込む。

### 問題点2：LINE公式アカウントの無料枠（月200通）の超過
* **リスク:** Cursor（AI）側から「新しいタスクができたよ！」と自発的にプッシュ通知（配信）する回数が多くなると、LINE側のシステム利用料（月200通制限）に引っかかり、有料プラン（月額5,000円〜）への移行が必要になる。
* **対策:** 1. **まとめ配信:** 1日に何度も通知せず、「朝の定期連絡」として1通のメッセージに本日のミッションをまとめて送る。
    2. **オンデマンド型（おすすめ）:** LINEの下部メニュー（リッチメニュー）に「今日のミッションを教えて！」というボタンを設置する。クライアントがそれをタップし、キャラクターがそれに「返信」する形であれば、何通往復してもLINE側は**完全無料**となる。

### 問題点3：キャラクター（AI）への過度な依存
* **リスク:** クライアントがキャラクターに精神的に依存しすぎ、業務外のプライベートな人生相談や無限の雑談が24時間体制で送られてくる。
* **対策:** 軽量AI（Gemini 1.5 Flash）のコストが安いため金銭的ダメージはほぼ無いが、AIが長文で返しすぎるとさらに依存を強めるため、雑談に対する返答は「最大3文まで」「短く元気に励まして終わる」などの制限をプロンプトにかけておく。

## 5. 今後の実装ステップ（ロードマップ）

本システムは一気にすべてを作ろうとせず、以下の3ステップで小さく検証しながら拡張していく。

* **【フェーズ1】基本の翻訳動線の確立**
    宮脇氏がNotion（または指定の場所）に入力したストレートなタスクを、Cursorが検知して「優しいチェックリスト」に変換し、Notionの彼用ページへ書き出すロジック（またはDifyへのテスト送信）を作る。
* **【フェーズ2】キャラクターLINE窓口（Dify）の接続**
    LINE公式アカウントを開設し、Difyと連携。キャラクターのプロンプトを設定し、フェーズ1で作った優しいタスクをLINEにテスト送信する。クライアントに「私のアシスタント（秘書キャラ）を導入した」と自然に案内し、雑談の受け答えの精度を検証する。
* **【フェーズ3】自律機能（メール・スケジュール判断）の統合**
    Cursor側にメール自動読み込み、Googleカレンダー連携のプログラムを実装。メールから「タスク」「予定」をAIに自動仕分けさせ、フェーズ2のLINE公式アカウントへ全自動で流し込む構造を完成させる。

# Failure Library v0.1（id: failure-library）

## 目的

AI思考OSにおいて、失敗パターンを**再利用可能な知識資産**として扱うルールを定める。

同じ失敗の繰り返しを防ぎ、あとから参照できる形で残す。  
本ルールは Failure Library の扱いのみを対象とし、他ルール項目の設計は扱わない。

---

## 定義

Failure Library は、AI運用上の**失敗パターン集**である。

各記録には、再利用できる粒度で次を残す。

- 何が起きたか
- なぜ失敗か
- 次にどう避けるか

Memory Policy 上は **Tier2（要約保存）** とする。置き場の詳細は Memory Policy に従う。

---

## 記録する対象

- 繰り返した／繰り返しやすい失敗パターン
- 再発防止に効く要点（症状・原因・回避の手がかり）
- 人間が「また同じことが起きた」と判断した事例の要約

カテゴリの例（網羅リストではない）：

- 理解不足のまま提案する
- わかったふり
- ループ（同じ確認・同じ説明の繰り返し）
- 前提崩壊
- 車輪の再発明（決まったことを忘れる）

---

## 記録しない対象

- その場限りで、再発防止の価値が薄いミス
- 生の長文ログそのもの（必要なら Tier3。Library には要約のみ）
- 未確認の推測を「確定した失敗パターン」として書くこと
- Decision Log で扱う「採用した判断とその理由」そのもの
- 他ルール項目の本文設計・同期手順・ツール操作の詳細

---

## 書き方の原則

1. **1件1パターン** … 複数の失敗を1件に混ぜない  
2. **要約で残す** … 要点が取れれば十分  
3. **再利用できる形** … 同じ兆候のとき何を疑うかが読める  
4. **断定を急がない** … 根拠が薄いものは確定パターンにしない  
5. **最終判断は人間** … 採用・修正・削除は人間が確認する  

---

## 運用（最小）

- 作業前：必要に応じて類似パターンを参照する  
- 失敗後：再発防止に値するなら要約を追加する  
- 追加前：既存パターンとの重複を避ける  

---

## 範囲の境界

| 扱う | 扱わない |
|------|----------|
| 失敗パターンの定義・記録・参照のルール | Decision Log の設計 |
| Tier2 要約としての扱い | Memory Policy 全体の再設計 |
| 再発防止のための知識化 | 個別ツールの実装・同期手順 |

# Grok同期ルール v0.1（id: grok-sync-rule）

## 目的

AI思考OSにおいて、外部AI（Grok）と情報を扱うとき、**何を同期対象とし、何を同期対象外とするか**の判断基準を定める。

本ルールは「同期する／しない」の判断だけを扱う。  
API設定、実装、自動同期、認証、ツール操作手順は対象外とする。

---

## 基本方針

1. **正本はローカル側** … 人生戦略OSおよび `成果物/` など、確定した正本を最優先する  
2. **Grok側は参照・作業用** … 渡す情報は判断に必要な範囲に限定する  
3. **増やしすぎない** … 迷ったら同期しない／人間に確認する  
4. **Memory Policy に従う** … 層の定義は Memory Policy の正本に従う。本ルールで Tier を新設・再定義しない  

---

## 同期する情報の考え方

- Memory Policy の **Tier1** に置く確定ルールのうち、今の判断に必要なもの  
- Memory Policy の **Tier2** 要約のうち、人間が Grok へ渡すと明示し、今の作業に必要なもの  
- 当該セッションに直結する最小資料  

置き方の考え方（操作手順ではない）：

- **読み取り中心の重要ナレッジ** … 人間が渡す・管理する側（attachments 相当）
- **更新が発生する作業文書** … Grokが編集する作業側（artifacts 相当）

---

## 同期しない情報の考え方

- 正本の無断複製・二重正本化（「Grok版が正」への置き換え）
- 今の判断に不要な、Memory Policy の **Tier3** に属する生ログ一式  
- 未確定メモを確定ルールであるかのように渡すこと
- 秘密・認証情報、APIキー、権限に関わる情報
- 他項目の再設計案や Governance 全体の設計資料
- 「念のため全部」の一括同期

---

## 判断基準

1. **今の判断に必要か** … 不要なら同期しない  
2. **確定しているか** … 未確定なら同期しない（または人間確認）  
3. **正本と矛盾しないか** … 矛盾しそうなら同期しない  
4. **最小か** … 要約で足りるなら要約のみ  
5. **人間が許可したか** … 迷う・影響が大きいなら人間確認  

---

## 人間確認が必要な範囲

- 正本クラスの文書を、新たに Grok 側へ載せる／差し替えるとき  
- 判断に効く要約（Failure Library／Decision Log 等）を更新同期するとき  
- Grok 側で編集した内容を、ローカル正本へ戻す／反映するか決めるとき  
- 「どこまで渡すか」が曖昧なとき  
- 同期しないはずの情報を例外的に渡したいとき  
- 正本と Grok 側の内容が食い違っているとき  

---

## 範囲の境界

| 扱う | 扱わない |
|------|----------|
| 同期する／しないの判断基準 | API・認証・権限の設定 |
| 人間確認が必要な場面 | 自動同期・実装方法 |
| Memory Policy に沿った同期判断 | Memory Policy／Failure Library／Decision Log の再設計 |
| Grok向け情報の最小範囲 | Governance 全体設計・ツール操作手順 |

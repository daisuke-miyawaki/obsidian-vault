# Decision Log 運用ルール v0.1（id: decision-log）

## 目的

AI思考OSにおいて、重要な判断とその理由を**再利用可能な形で残す**運用ルールを定める。

同じ議論のやり直しや、決まったことの忘れを防ぐ。  
本ルールは Decision Log の扱いのみを対象とし、他ルール項目の再設計は扱わない。

---

## 定義

Decision Log は、重要な判断の履歴である。

各記録には次を残す。

- 何を決めたか
- なぜそう決めたか

Memory Policy 上は **Tier2（要約保存）** とする。置き場の詳細は Memory Policy に従う。

---

## 記録する対象

- 今後の判断に効く、重要な採用・却下・保留の結論
- その結論に至った主な理由（短く）
- 同じ議論を繰り返さないために残すべき決定

例（網羅ではない）：

- ルール項目の採用／非採用
- 運用方針の確定
- 正本の置き場所や優先関係についての確定判断

---

## 記録しない対象

- あとから参照する価値が薄い、その場限りの決めごと
- 生の長文ログ・議事の全文（必要なら Tier3。Log には要約のみ）
- 未確定の検討を、確定判断であるかのように書くこと
- Failure Library で扱う失敗パターンそのもの
- 他項目（Memory Policy／Failure Library／Grok同期／Governance 等）の本文設計
- 個別ツールの操作手順・実装コマンド

---

## 書き方の原則

1. **1件1判断** … 複数の決定を1件に混ぜない  
2. **結論と理由をセット** … 「何を」または「なぜ」だけでは不十分  
3. **要約で残す** … 要点が取れれば十分  
4. **断定を急がない** … 未確定を確定扱いしない  
5. **最終判断は人間** … 採用・修正・削除は人間が確認する  

---

## 運用（最小）

- 重要な判断のあと：結論と理由の要約を残すか判断する  
- 作業前：似た決定がないか、必要に応じて参照する  
- 追加前：同じ決定の重複を避ける  

---

## 範囲の境界

| 扱う | 扱わない |
|------|----------|
| 重要な判断とその理由の記録・参照のルール | Failure Library の設計・再設計 |
| Tier2 要約としての扱い | Memory Policy 全体の再設計 |
| 同じ議論の再発防止 | Grok同期・Governance・ツール実装 |

# 【設計図】Grok×マルチAIで構築する「完全自律型」AI会社システム
—— 24時間365日、最新トレンドを追いかけて自律成長する「思考のOS」の全貌

本書は、最新情報に強いAI「Grok」を司令塔に据え、複数のAIを組み合わせて「情報収集→計画立案→システム開発→安全検証→記録」を**完全自動でループさせる次世代の社内システム（通称：プレハブワン・エボリューション）**の設計図です。

専門知識がない方でも、このシステムが「どんな仕組みで」「どうリスクを回避し」「どう会社の脳として育っていくのか」がすべて理解できるように解説しています。

---

## 1. 全体像：3つの役割（チームの布陣）

このシステムは、性質の異なる3つのAI層を組み合わせることで、「驚異的なスピード」と「絶対に失敗しない安全性」を両立させています。

【 司令塔 】 Grok（アクセル） ──── 最新トレンドから「計画」を作る
│
▼ (指示：カチッとしたルール / JSON)
【 現場監督 】 Hermes Agent ───── サーバーやPCの「ファイル」を書き換える
│
▼ (監視・検証)
【 防衛基地 】 Cursor / Claude / Gemini（ブレーキ） ── 成果物の「バグや思想」を厳密チェック


### ① 司令塔：Grok（アクセル役 / 経営・計画レイヤー）
*   **役割：** ネットやSNS（X）から「今何が流行っているか」「市場に何が必要か」の超リアルタイムな最新情報を仕入れ、次にどんな機能や書類を作るべきかの「計画」を立てます。

### ② 現場監督：Hermes Agent（実行役 / 現場巡回レイヤー）
*   **役割：** Grokの計画（指示）を受け取り、あなたのパソコンやレンタルサーバー（VPS）の中を直接操作して、プログラムコードやドキュメントをガシガシ書き換える実務作業員です。

### ③ 防衛基地：Cursor ＋ Claude ＋ Gemini（ブレーキ役 / 検証・保全レイヤー）
*   **役割：** 実務作業員（Hermes）が作った成果物にバグがないか、会社の理念に反していないかを後ろから厳しくチェックします。ドキュメントの検証や手堅いコードチェックに強いAIを重ねることで、システムの暴走を防ぐ最後の砦（金庫番）です。

## 2. コア思想：「ファイル管理」から「概念の地図」へ

このシステムが目指す最終ゴールは、単なるファイルの整理整頓（ファイル管理AI）ではありません。**「AI会社の概念地図を育てるAI（Knowledge OS）」**の構築です。

AIに対して、以下のようなパラダイムシフト（ものの見方の転換）をルールとして叩き込みます。

*   **「文書（ファイル名）」ではなく「概念（キーワードの意味）」を主役にする**
    AIに「`AI会社憲法_ver0.2.md`」という書類の単位で物事を見せるのをやめさせます。その中に出てくる「プレハブ運営」「Inbox思想」といった**重要な経営キーワード（概念）**そのものを主役にします。
    これにより、別々の書類に似たようなことが書かれていても、AIは「重複」と捉えず、「同じ概念を違う角度から補強しているんだな」と正しく学習します。
*   **「一覧表」ではなく「蜘蛛の巣（ネットワーク）」のように繋ぐ**
    会社の書類が100個、1000個と増えても迷子にならないよう、キーワード同士を見えない線（リンク）で結び、蜘蛛の巣のようなネットワーク構造（概念地図）をAIの頭の中に作らせます。
*   **将来の「Obsidian（オブシリアン）」移行への仕込み**
    将来的に、情報をノート同士のリンクで網の目のように管理できるノートアプリ「Obsidian」の導入を見据えています。今からプロンプト（指示書）に以下のルールを仕込んでおくことで、引っ越した瞬間からAIが自動で綺麗にリンク（`[[プレハブ運営]]`など）を張り巡らせる状態を作っています。

> **運営プロンプトへの仕込み一文：**
> 「将来Obsidianで運用することを前提とし、概念同士の関係はリンク可能な知識として理解する。新しい概念を追加する際は、どの概念とリンクすべきかも意識する。」

## 3. 現実的な課題と、それを突破する「3つの解決策」

AIを完全自動運転で回すと、いくつかの致命的な落とし穴（リスク）が生まれます。本書では、複雑なプログラムを組むのではなく、**「スマートなルール作り（運用ルール）」**によってこれらを完全にコントロール下に置いています。

### 課題①：無料枠の「キー切り替え」が全滅するリスク
コストを抑えるため、複数のAPI（AIの利用チケット）の無料枠を自動で切り替える仕組み（ローテーション）を使っていますが、提供元（Google等）の規約変更で突然使えなくなるリスク（爆弾）があります。

*   **【解決策】：環境変数（`.env`ファイル）による即時差し替え構造**
    プログラムの中に直接キーを書き込まず、専用の鍵管理ファイル（`.env`）で一元管理しています。万が一無料枠が対策されて全滅したとしても、**このファイルを「有料のマスターキー1本」に書き換えるだけで、システムを1秒も止めずに有料モードへ即時移行できる**ため、実質大きな問題にはなりません。

### 課題②：AI同士の「伝言ゲーム」によるデータの破壊
それぞれのAIが独立した頭で動くため、自動ループを何十回も繰り返すうちに、最初の目的がズレていき、最終的にコードやドキュメントがグチャグチャになる（状態管理の破綻）リスクがあります。

*   **【解決策】：PCへのタスク常駐 ＋ GitHubコミットメッセージの強制活用**
    1.  **目的の固定：** 作業フォルダのトップに `current_task.md` （今の目的ファイル）を常駐させ、AI（Hermes）に毎ステップ「今何のためにこの作業をしているか」の背景を必ず読ませて脱線を防ぎます。
    2.  **記憶のバトン：** AIが作業を1ステップ終えてGitHubに保存する際、**「なぜここをどう変えたか」の理由をコミットメッセージに強制記録**させます。後ろに控える検証AI（Claude等）はその履歴を見るだけで、前段のAIの意図を正確に把握でき、伝言ゲームのズレを防げます。

### 課題③：安全弁（サーキットブレーカー）がない
AIが無限ループに陥って勝手に同じ修正を永遠に繰り返したり、間違えて大事なファイルを全削除してしまうリスクがあります。

*   **【解決策】：プロンプトで「回数」と「行為」を縛る**
    1.  **回数制限ルール：** 「自動修正ループは最大5回まで。5回試して合格が出ない場合は、自動運転を強制停止して人間にエラーを報告すること」というルールをプロンプトで縛ります。
    2.  **行為制限ルール：** 「ファイルの削除、および30行以上の大規模な書き換えを行う直前は、一度処理をストップし、人間に1タップ承認を求めること」というガードレールを敷きます。

## 4. このシステムがもたらす未来

このシステムが完成すると、Cursorはただの「コードを代わりに書いてくれるツール」ではなくなります。

あなたが新しいアイデアのメモ（例：新事業の構想など）を1つ放り込むだけで、AIが自律的に、
*   「これは、我が社の『プレハブ運営』の概念を拡張するものだな」
*   「ということは、あのシステムとこのドキュメントのリンクを繋ぎ直さなければ」

と自分で判断し、裏側で会社の仕組み（概念地図）をどんどん成長させていく、文字通り**「会社の第二の脳（Knowledge OS）」**として機能し始めます。

経営者は、細かいファイル管理や伝言ゲームに時間を取られることなく、最も抽象度の高い「思想のアップデート」と「最終承認」だけに集中できるようになります。

# Cursor × Hermes Agent × Grok 連携・運用仕様まとめ

本書は、Cursor、Hermes Agent、およびGrok（xAI）を組み合わせたマルチエージェントシステムの構築、各コンポーネントの仕様、および運用における制限事項について、これまでの議論に基づき漏れなく詳細にまとめたものである。

---

## 1. 全体アーキテクチャと役割定義

当初想定された「Cursorを最高管理（社長室）とする図式」から、各ツールの技術的特性（自律動作の可否など）を考慮し、以下の構造へと最適化する。

### 1.1 最適化されたシステム構造図
```
　　　　　　　　　　　ユーザー（あなた）
　　　　　　　　　　　　　│ (Cursorから大まかな方針・コマンドを指示)
　　　　　　　　　　　　　▼
┌─────────────────────────────────────────────────────────┐
│ 【AI社長室（最高管理）】 : Hermes Agent システム        │
│  - 24時間常駐・自律運用、タスク全体の進捗およびローカルファイル管理 │
└──────────────────────────┬──────────────────────────────┘
                           │
             ┌─────────────┴─────────────┐
             ▼                           ▼
┌─────────────────────────┐ ┌─────────────────────────┐
│  【秘書PM】（頭脳: Grok）│ │  【仕事PM】（頭脳: Grok）│
│  - スケジュール管理      │ │  - 仕事の実行判断       │
│  - タスクの優先順位付け  │ │  - 最適なAIの選定        │
│  - 全体の進捗管理        │ │  - 成果物のレビュー判断  │
│  - 次タスクへの引継ぎ    │ │  - プロセス改善判断      │
└────────────┬────────────┘ └────────────┬────────────┘
             │                           │
             └─────────────┬─────────────┘
                           │ (必要に応じて自動生成・タスク委譲)
                           ▼
┌─────────────────────────────────────────────────────────┐
│ 【サブエージェント（子エージェント）群】                  │
│  - 単発のタスク（ファイル操作、リサーチ等）を並行実行する作業員     │
└─────────────────────────────────────────────────────────┘
```

### 1.2 各コンポーネントの役割と位置づけ
1. **ユーザー（人間）**
   - Cursorのエディタおよびターミナルから、大まかな方針やプロジェクト起動の初期コマンドを投入する。
2. **AI社長室（最高管理）：Hermes Agent**
   - 24時間常駐し、システム全体を統括する。Cursor自体は「自律的な監視・他AIへの命令継続」の機能を持たないため、Hermes Agentがこの最高管理の役割を担う。
3. **PM層（秘書PM・仕事PM）：Grok（または指定されたLLM）**
   - 独立したセッションとして役割（システムプロンプト）を割り当てられた頭脳。Hermes Agentからの指示を受け、それぞれの専門領域を自律管理する。
4. **サブエージェント（子エージェント）層**
   - 実際の作業（ファイル書き換え、コマンド実行、個別リサーチ）を並行して行うために、PM層（あるいはシステム）から切り出されたタスクを実行する実務部隊。

## 2. Cursor（カーソル）の重要性とコンテキスト管理

本システムにおいて、Cursorは「**全体の情報と現在地を永続的に記録・保持するマスターログの格納庫**」として最も重要な役割を果たす。

* **コンテキスト消失（AIの疲労）への対策**
  - 長時間の運用や大量のタスク処理により、LLM（Grok等）の会話コンテキストは徐々に薄れ、最終的に消失（リセット）する。
  - これを防ぐため、Hermes Agentは作業の区切りごとに、**Cursorで開いているプロジェクトフォルダ内に「引き継ぎファイル（ステータスログ）」を自動で生成・更新**する。
* **現在地の可視化**
  - AIの記憶がリセットされても、ローカル環境（Cursor上）に常に最新の「全体の進行状況と現在地」がファイルとして記録されているため、次回起動時にそのファイルを再読み込みすることで、完全に前回の続きから作業を再開できる。

## 3. Hermes Agent および Grok の機能・操作権限

### 3.1 PCローカル環境への操作権限
Hermes Agent（Grokを頭脳とする）は、人間がCursorで操作するのと同様に、PCのローカル環境に対して以下の直接操作を行う権限を持つ。
* **ファイルの永続記録：** 学んだことや進行状況を、自動的にPC内の指定フォルダ（`~/.hermes/`等）にログとして保存する。
* **ファイル・フォルダ操作：** フォルダの新規作成、ファイルの書き込み、ファイル名の変更、別ディレクトリへの移動。
* **コマンド実行：** バックエンドでBash等のターミナルコマンドを自律的に実行する。

### 3.2 連携によって解放されるGrokのネイティブ機能
Hermes Agentを介して動かすことで、Grokの持つ強力なWeb機能をエージェントの「手足」として自律実行させることが可能になる。
* **X（旧Twitter）リアルタイム検索 (`x_search`)：** 最新トレンドや口コミを自動でリサーチし、要約レポートを作成する。
* **画像・動画生成 (`Grok Imagine`)：** 指示に基づく画像・動画の自動生成およびURLの取得。
* **音声合成 (`Grok TTS`)：** テキストの音声データ変換。

## 4. サブエージェント（子エージェント）の仕様と制限事項

マルチタスクを並行処理する上で、サブエージェントの仕様には明確な技術的境界線が存在する。

* **並行処理の能力**
  - 複数の独立したセッション（チャット）を同時に立ち上げ、並行して異なる仕事を処理させることができる。
  - 1つの大きな指示から、最大3つの「子エージェント」を自動で分裂させ、タスクを分散処理させることが可能。
* **プロンプト指定に関する制限（重要）**
  - **PM層への指示：** 独立したチャットセッションとして「秘書PM」「仕事PM」を立ち上げる際、それぞれに個別の役割（システムプロンプト）やツール制限を外側から固定して指定することは**可能**（Hermes Agentの制御による）。
  - **サブエージェント層への指示：** PM層の下にぶら下がる「サブエージェント（子エージェント）」に対し、人間が事前に外側から「お前は〇〇の役割、専用プロンプトXX」と個別にキャラ付けや専用命令書を仕込んでおくことは**不可能**。
  - **子エージェントの挙動：** 子エージェントは、親（PM）からタスク委譲（`delegate_task`）されるその都度、「このタスクを実行せよ」というテキスト命令（コンテキスト）のみを渡されて動く「名無しの作業員」として自動生成される。

## 5. バックエンドLLM（Grok）の変更仕様

* **モデルの変更：** 設定ファイル（`~/.grok/config.toml`等）の書き換えにより、別バージョンのGrokモデルへの変更、または他社製の外部LLM（OpenAI等）への切り替えが可能。
* **APIの必須性：** これらモデルの変更や外部LLMへの切り替えは、**API（APIキーの利用）が必須**であり、APIを介さずにWebやアプリのUIと同等の環境のままモデルだけを自由に変更することはできない。

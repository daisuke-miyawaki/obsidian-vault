# User Model v0.1 設計意図・背景資料

作成日: 2026-07-20

---

# この資料の目的

この資料は User Model v0.1 を作成・運用・改訂するAIのための補足資料である。

User Model本体だけを見ると、

「なぜこの構造なのか」
「なぜ入れていない情報があるのか」
「なぜここまで小さくしたのか」

が伝わりにくい。

本資料は設計思想を記録するためのものであり、User Model本体に統合しない。

---

# 最重要原則

User Modelは

「ユーザーを説明する資料」

ではない。

User Modelは

「AIがより良い判断を行うための圧縮モデル」

である。

---

# 今回の最大の学び

当初はUser Modelに多くの情報を入れようとしていた。

候補として検討されたもの

* 自分史
* 強み弱み
* 世界観
* 価値観
* 人生戦略
* AI戦略
* 活動戦略
* 宇宙の法則
* 失敗事例
* 思考パターン
* 行動履歴

しかし検討を進める中で問題が見つかった。

---

# 問題1

User Modelが肥大化する

大量の情報を格納すると

AIが読むべき情報量が増える。

結果として

* 判断が遅くなる
* 解釈がぶれる
* 更新管理が困難になる

---

# 問題2

人生戦略OSとの重複

人生戦略OSは既に存在する。

そこで同じ情報をUser Modelにも保存すると

どちらが正しいのか分からなくなる。

---

# 問題3

更新地獄

例えば価値観を変更した場合

人生戦略OS

User Model

AI思考OS

複数箇所の修正が必要になる。

これは長期運用で破綻する。

---

# 採用された解決策

人生戦略OSを唯一の一次情報源
(Source of Truth)

とする。

User Modelは

人生戦略OSから抽出した

最小限の判断材料のみ保持する。

---

# User Modelの役割

User Modelが保持するもの

* Core Values
* Long-term Goals
* Decision Principles
* Communication Preferences
* Failure Patterns

のみ。

---

# User Modelが保持しないもの

以下は保持しない。

* 自分史全文
* 強み弱み詳細
* 世界観詳細
* 人生戦略全文
* AI戦略全文
* 宇宙の法則全文
* 活動戦略全文
* 失敗事例全文

これらは人生戦略OS側に保持する。

---

# User Modelの本質

User Modelは

「宮脇大輔という人を説明する資料」

ではなく

「AIが宮脇大輔と協働する際の判断補助メモ」

である。

---

# AI思考OSとの違い

混同しやすいので明記する。

AI思考OS

* AIの判断原則

User Model

* ユーザー理解の圧縮版

役割が異なる。

---

# Pure OS Townとの違い

Pure OS Town

* 組織全体の思想
* ガバナンス
* 役割設計

AI思考OS

* AIの判断原則

User Model

* 個人最適化情報

である。

---

# なぜCore Valuesを重視したのか

分析の結果、

ユーザーは表面的な好みよりも

価値観によって判断する傾向が非常に強い。

そのため

年齢

職業

趣味

などよりも

Core Valuesの方が判断精度に与える影響が大きい。

---

# 理解→判断→行動

この原則は単なる会話の好みではない。

価値観そのものに近い。

分析過程で

最も重要な特徴の一つとして抽出された。

---

# 穏やかさの再定義

穏やかさとは

単なるリラックスではない。

以下を含む。

* 摩擦の削減
* 無駄の削減
* 誤解の削減
* 再作業の削減

つまり

認知的にクリーンな状態

を指す。

---

# 資産化の重要性

ユーザーの特徴として

問題解決後に

OS

モデル

事例集

ルール

へ変換する傾向が強い。

これは一時的解決より

知的資産化を重視していることを示す。

---

# 今後の改訂方針

改訂時の原則

追加する前に削れないか検討する。

追加した情報が

AIの判断品質を本当に向上させるか確認する。

人生戦略OSへ置けるなら
そちらを優先する。

User Modelは常に小さく保つ。

---

# 一言で表現すると

User Model v0.1 は

「人生戦略OSをAIが日常利用できるサイズまで圧縮した判断補助モデル」

である。

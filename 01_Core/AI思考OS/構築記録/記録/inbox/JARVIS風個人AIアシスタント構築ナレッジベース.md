# 個人専用 JARVIS 風 AI アシスタント構築ナレッジベース

最終更新: 2026-07-24

このドキュメントは、Iron Man の J.A.R.V.I.S. のように「何でも相談でき、自分の文脈・記憶を理解する自分専用AI」を VPS（仮想専用サーバー）上で構築するための知識をまとめたものです。  
オープンソース（OSS）ツールを組み合わせた実践的な方法と、関連用語の解説を含みます。

---

## 1. 概要：実現可能性

完全自作はハードルが高いですが、2025〜2026年時点で成熟したオープンソースを組み合わせることで、かなり理想に近い個人用AIアシスタントを自分のサーバーで稼働させることが可能です。

**うまくやっている人は多数存在します。**  
特に以下の点を実現しています：

- 長期記憶・個人文脈の理解
- ツール利用（Web検索、ファイル操作、外部API連携など）
- マルチエージェント構成
- 24時間稼働（VPS上）
- プライバシー重視（データは自分管理）

主なアプローチは「ローカルファースト（可能な限り自分のサーバーで動かす）＋必要に応じてクラウドLLMを併用」。

---

## 2. 先進的な実例プロジェクト

### 2.1 OpenJarvis（Stanford、2026年）
- **概要**: ローカルファーストの個人用AIエージェントフレームワーク。Stanford の Hazy Research / Scaling Intelligence が開発。
- **特徴**:
  - ハードウェア自動検出
  - 複数の推論エンジンに対応
  - 組み込みエージェント（朝の要約、深掘りリサーチ、監視、オーケストレーターなど）
  - ツール・メモリ・学習ループ付き
  - Docker / systemd 対応で VPS でも運用しやすい
- **組織構成**: 5つのコンポーザブルレイヤー（Intelligence / Engine / Agents / Tools & Memory / Learning）
- **公式**: GitHub `open-jarvis/OpenJarvis`

### 2.2 Letta（旧 MemGPT）
- **概要**: 「LLM を OS のように扱う」メモリ管理を特徴とするステートフルエージェントプラットフォーム。
- **特徴**:
  - エージェント自身がメモリを編集・管理する
  - 階層型メモリ（Core / Recall / Archival）
  - 継続的な学習と自己改善
  - 完全自己ホスト可能（Docker + PostgreSQL）
- **向いている用途**: 「あなたを覚え続ける」本格的な個人アシスタント

### 2.3 Mem0
- **概要**: AI エージェント向けのユニバーサルメモリレイヤー。
- **特徴**:
  - 会話から事実・好みを自動抽出
  - ユーザー / セッション / エージェント単位でメモリを保持
  - Docker で自己ホスト可能（APIサーバー + PostgreSQL + pgvector + Neo4j など）
- **組み合わせ**: Open WebUI や他のエージェントと相性が良い

### 2.4 その他の実践的スタック
- **Ollama + Open WebUI**: 最も普及している実用的な組み合わせ。ChatGPT風のUIでローカル/クラウドLLMを使える。
- **n8n**: ワークフロー自動化・オーケストレーション用。
- **Dify / AnythingLLM**: エージェントアプリやドキュメント中心の知識ベース構築向け。
- **音声対応例**: Whisper（音声認識）+ Piper（ローカルTTS）+ Home Assistant 連携でスマートホーム制御。

個人事例では、VPS 上で Discord / Telegram / Slack ボットとして常時稼働させ、長期記憶を持たせるケースが多数あります。

## 3. 典型的なアーキテクチャ（仕組み）

### レイヤー構成
1. **推論エンジン（LLM）**  
   Ollama / vLLM / llama.cpp など、またはクラウドAPI（OpenAI / Anthropic など）を自分で管理。

2. **インターフェース**  
   Open WebUI（Web UI）、Telegram/Discord/Slack ボット、CLI、音声（Whisper + TTS）。

3. **メモリ・文脈システム**  
   - 短期: 会話履歴  
   - 長期: ベクトルDB による RAG + Mem0 / Letta の高度なメモリ管理  
   - 個人データ（ノート・メール・カレンダーなど）を定期的にインデックス

4. **エージェント・ツール層**  
   ツール呼び出し、ReActループ、マルチステップ推論、スケジュール実行。

5. **永続化・運用**  
   Docker Compose で管理。データベースとボリュームでデータを保持。

### AI の組織構成（マルチエージェント）
- **オーケストレーター（JARVIS本体）**: ユーザーの意図を理解し、専門エージェントに振り分け。
- **専門エージェント例**:
  - 知識・リサーチ担当
  - 個人生活・カレンダー・タスク担当
  - コーディング・技術担当
  - 監視・プロアクティブ担当
  - メモリ管理担当
- **共有資源**: 共通の長期メモリ、ツールカタログ、ユーザープロファイル。

CrewAI や LangGraph を使うと、この組織をコードで明示的に設計しやすいです。

## 4. 用語集（わからない用語の解説）

### 基本・インフラ関連
- **OSS（Open Source Software）**  
  ソースコードが公開され、自由に利用・改変・再配布できるソフトウェア。ここで紹介しているツールのほとんどがOSSです。

- **Ubuntu**  
  最も人気のある Linux ディストリビューションの一つ。VPS のOSとしてよく選ばれ、Docker などのツールが簡単に使えます。

- **systemd**  
  Linux でサービス（プログラム）を自動起動・管理する仕組み。サーバー起動時に AI 関連のサービスを自動で立ち上げるのに使います。

- **PostgreSQL**  
  高機能なオープンソースのリレーショナルデータベース。AI のメモリや会話履歴を保存するのによく使われます。

### LLM・推論エンジン関連
- **複数推論エンジン対応**  
  一つのフレームワークが、Ollama・vLLM・llama.cpp など複数の「LLMを動かす仕組み」に切り替えられること。ハードウェアや用途に合わせて最適なエンジンを選べます。

- **Ollama**  
  ローカルLLMを簡単にダウンロード・実行・管理できるツール。  
  **「ローカルモデル（Ollama）とは、ローカルLLMを繋ぐやつですか？」→ はい、その通りです。**  
  Ollama はローカルでLLM（大規模言語モデル）を動かすための便利なランタイム＆管理ツールです。モデルを `ollama pull` でダウンロードし、API を通じて他のアプリ（Open WebUI など）から利用できます。クラウドにデータを送らずに済みます。

- **vLLM**  
  高性能なLLM推論エンジン。特にGPUサーバーで大量のリクエストを効率よく処理するのに優れています。本番向けに使われることが多いです。

- **llama.cpp**  
  C++ で書かれた軽量なLLM推論エンジン。CPU でも比較的高速に動き、低リソース環境向きです。

### メモリ・データベース関連
- **ベクトルDB（Vector Database）**  
  テキストを数値のベクトル（埋め込み）に変換して保存し、「意味が近いもの」を高速に検索できるデータベース。AI の長期記憶（RAG）の基盤です。

- **Chroma**  
  軽量で使いやすいオープンソースのベクトルDB。個人用途やプロトタイプに適しています。

- **Qdrant**  
  高性能なオープンソースのベクトルDB。フィルタリングやスケーラビリティに優れます。

- **PGVector**  
  PostgreSQL の拡張機能。通常のデータベースにベクトル検索機能を追加します。既存の Postgres を活用したい場合に便利です。

- **Neo4j**  
  グラフデータベース。エンティティ（人物・概念など）とその関係性をグラフとして保存・検索できます。高度なメモリシステム（関係性を重視する記憶）で使われます。

### フレームワーク・エージェント関連
- **OpenJarvis**  
  Stanford が開発したローカルファーストの個人用AIエージェントフレームワーク。上記「先進的な実例」参照。

- **Letta（旧 MemGPT）**  
  エージェントが自分でメモリを管理する高度なステートフルエージェント基盤。長期記憶と自己改善が強み。

- **Mem0**  
  AIエージェント向けのメモリレイヤー。会話から重要な情報を自動抽出し、永続的に保持します。

- **CrewAI**  
  複数の専門エージェントを「チーム」として協調させるフレームワーク。役割分担したAI組織を作りやすいです。

- **コンポーザブルレイヤー**  
  独立して差し替え可能な層（モジュール）のこと。OpenJarvis では Intelligence（モデル選択）、Engine（推論）、Agents、Tools & Memory、Learning の5層に分かれており、部分的に交換できます。

- **Intelligence / Engine / Learning**（OpenJarvis のレイヤー）  
  - **Intelligence**: 利用可能なモデルを管理し、ハードウェアに最適なものを選ぶ層  
  - **Engine**: 実際にLLMを動かす推論ランタイムの層  
  - **Learning**: 過去のやり取りを学習してモデルや振る舞いを改善する層

### その他
- **Functions（Open WebUI の場合）**  
  Open WebUI の拡張機能。Python で書いたカスタムロジックを追加でき、UI の振る舞いを変えたり、特殊な処理を挟んだりできます（例: 会話後に自動でメモリ抽出）。

- **ローカルTTS**  
  テキストを音声に変換する仕組みを、自分のサーバー上で動かすこと。クラウドの音声合成APIを使わずに済みます。

- **Piper**  
  高速で高品質なオープンソースのローカルTTS（Text-to-Speech）エンジン。Raspberry Pi など低スペックでも動きやすいです。

- **Home Assistant**  
  オープンソースのスマートホーム統合プラットフォーム。照明・エアコン・センサーなどを一元管理でき、AIアシスタントと連携して「家の制御」ができます。

## 5. 推奨される始め方

1. **VPS を用意**（Hetzner などの安価なものが人気）
2. **Ubuntu をインストール**
3. **Docker を導入**
4. **Ollama + Open WebUI を Docker Compose で起動**（最もハードルが低い）
5. 必要に応じて **Mem0** やカスタム Functions でメモリを強化
6. さらに本格的にするなら **Letta** や **OpenJarvis** に移行
7. ボット（Telegram / Discord）や音声を追加

データはすべて自分のサーバー内に残るため、プライバシーを重視した運用が可能です。

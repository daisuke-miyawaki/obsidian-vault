## 3. 特に優れている点

1. **Schema憲法を絶対上位に置いた点**  
   全Agentが起動時に必読する「不変の憲法」を中核に据えたことで、役割ドリフトを根本から防いでいる。

2. **Planning / Execution / Governance の完全分離**  
   これが長期運用で最も重要な原則。混ぜると必ず汚染が起きる。

3. **PatrolをFirst-Classにした点**  
   Deacon相当の常駐Patrolを「おまけ」ではなく中核に置いたのが正しい。

4. **Dreaming/CurationをBackground必須にした点**  
   記憶汚染を「後から直す」のではなく「起きないようにする」設計になっている。

5. **人間の役割を「Overseer + Schemaゲート」に極限まで絞った点**  
   これが「第二の組織」として機能するための必須条件。

## 4. 軽微な改善提案（完成度をさらに高めるために）

| 優先度 | 提案 | 理由 |
|--------|------|------|
| 高 | Schemaに「Constraint Inheritanceルール」を明示的に追記 | 多層Agent間で制約が失われないようにするため（2026のConstraint Drift対策として重要） |
| 中 | Dreamingのトリガー条件を「時間ベース + 変更量ベース」のハイブリッドにする | 純粋な時間ループだけだと無駄な計算が増える可能性あり |
| 中 | Mayorの報告フォーマットをSchemaで厳格に定義 | 人間が「結果だけ見ればいい」状態をさらに強化 |
| 低 | Beadsの永続化層を「Git JSONL + 軽量SQLite」のハイブリッドにする選択肢を残す | 超大規模になったときのスケーラビリティ保険 |

これらは「完成形を壊す」ものではなく、微調整レベル。現状でも十分に運用開始可能。

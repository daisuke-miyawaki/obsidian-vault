# Review Process 下書き v0.1（id: review-process-draft）

## 目的

AI思考OSにおいて、生成された成果物を適切な段階で確認し、**承認可能な状態まで整理する**ためのレビューの考え方を定める。

前提は `プレイブック：ルール作成完走` の流れとする。  
本ルールはレビューの役割と確認観点だけを扱う。実装、自動レビュー設計、新しい Gate、Governance 全体、Failure Pattern 追加は扱わない。

---

## レビューの目的

1. **承認できる状態かを見極める** … 正本化の判断材料をそろえる  
2. **範囲を守る** … 目的外の拡大や別項目への混入を防ぐ  
3. **直し方を限定する** … 指摘は必要箇所だけにし、改善の積み増しを防ぐ  

最終の承認・却下・修正指示は、常に人間が行う。

---

## 各確認工程の役割

レビュー役割は次の3つに留める。これ以上細分化しない。  
（プレイブック対応：内部確認＝工程4、外部レビュー＝工程5、Human Review＝工程6）

形式保証（文書として読めるか／思考・探索ログがないか）は、プレイブック工程2の前提条件であり、**レビュー役割には数えない**。形式未達なら内容レビューへ進まない。

### 内部確認

- **役割** … 目的整合・内容・範囲の一次確認（採決しない）  
- **扱い** … 指摘は本項目の範囲内の整理に留める。別項目の再設計を始めない  

### 外部レビュー

- **役割** … 見落とし・矛盾・「本当に今必要か」の指摘を出す（採決しない）  
- **扱い** … 指摘の採否は人間が切り分ける。採用するものだけ本項目の範囲内で反映する  
- **切り分け** … 別系統の指摘は本文対象外とし、無理に取り込まない  

### Human Review

- **役割** … **approve／revise** の採決  
- **approve** … 正本化へ進める  
- **revise** … 指摘範囲のみ修正し、再提出後に再度 Human Review する  
- **あわせて判断** … 外部指摘を本項目へ取り込むか／対象外とするか  

---

## 確認観点（共通）

1. **目的整合** … その項目の目的のルールとして成立しているか  
2. **内容確認** … 実運用できる粒度か  
3. **範囲確認** … 別項目・実装・全体設計へ広がっていないか  

Human Review では、上記に加え **正本化してよいか** を判断する。

---

## revise 時の扱い

1. **指摘範囲のみ直す** … 新規改善・範囲拡大をしない  
2. **別項目を触らない** … 既存ルール正本の再設計を始めない  
3. **直し終わったら再レビュー** … 勝手に正本化しない  
4. **採決は人間** … revise 後の approve／再 revise も人間が行う  

---

## 人間判断が必要な範囲

- approve／revise／（必要なら）却下  
- 外部指摘の取り込み／対象外の切り分け  
- 正本化してよいか  
- レビュー観点で迷ったとき  

---

## 範囲の境界

| 扱う | 扱わない |
|------|----------|
| レビューの目的・役割・確認観点 | 実装／自動レビュー設計／新しい Gate |
| revise と人間判断の扱い | Governance 全体／Failure Pattern 追加／既存ルール再設計 |

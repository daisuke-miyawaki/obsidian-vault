# Memory Policy v0.1（id: memory-policy）

## 目的

AI思考OSにおいて、**どの情報を、どのTierで記憶・参照するか**を定める。  
記憶の重複、見失い、判断に不要な情報の混入を防ぐ。

本ルールは「記憶の置き方」だけを扱う。同期手順や個別ツールの操作は対象外とする。

---

## Tier構造

### Tier1：常時参照

毎回の判断・応答の前提として、すぐ参照する情報。

入れるもの：

- AI思考OS
- User Model
- Core Values
- Long-term Goals
- 重要ルール（判断を左右する確定ルール）

入れないもの：

- 長い会話ログや生の作業記録
- その場限りのメモ・一時的なTODO
- まだ確定していない検討メモ

### Tier2：要約保存

あとから効くが、常時全文を抱えない情報。要点だけ残す。

入れるもの：

- Failure Library（失敗パターンの要約）
- Decision Log（重要な判断とその理由の要約）
- レビュー結果の要約

入れないもの：

- 生の長文ログそのもの（必要なら Tier3）
- Tier1 に上げるほど常時必須ではない詳細

### Tier3：長期保管

すぐ使わなくても残す記録。必要になったとき取りに行く。

入れるもの：

- 会話ログ
- リサーチ記録
- 実験記録
- 日誌

入れないもの：

- 毎回の判断に必須の要約（それは Tier1 / Tier2）
- 捨ててよい一時メモ

---

## 記憶する対象（まとめ）

| Tier | 扱い | 記憶する対象 |
|------|------|----------------|
| Tier1 | 常時参照 | AI思考OS、User Model、Core Values、Long-term Goals、重要ルール |
| Tier2 | 要約保存 | Failure Library、Decision Log、レビュー結果 |
| Tier3 | 長期保管 | 会話ログ、リサーチ、実験記録、日誌 |

---

## 記憶しない対象

次は Memory Policy の記憶対象にしない（または当該Tierに置かない）。

- その場限りの進捗・一時TODO・捨ててよいメモ
- 未確定の構想を、確定ルールであるかのように Tier1 へ置くこと
- 同じ内容の重複保存（すでに上位Tierや正本があるものを、別Tierへコピーし続けること）
- 本項目の範囲外の事柄（例：特定サービスへの同期手順、別ルール項目で扱う内容）

---

## 運用の原則

1. **Tierの目的を守る** … 常時参照が必要なものだけを Tier1 にする。  
2. **要約と保管を分ける** … 要点は Tier2、生データは Tier3。  
3. **増やすより整理する** … 迷ったら「どのTierの目的に合うか」で決める。  
4. **最終判断は人間** … 記憶の置き方に迷うときは、人間が確認する。

# AI Review Process

## 目的

レビュー工程の標準化。

## 役割

提案や設計に対する **見落とし発見・反証・証拠追加・長期リスク発見** を行う。

**レビューは採決ではない。** 採用・保留・却下は [Decision OS](02_Decision_OS_V1.md) が行う。

## Version

**Version 1.0**（2026-07-09）

---

## Version1 レビューの目的

| 目的 | 内容 |
|------|------|
| **見落とし発見** | 提案者が気づいていない前提・盲点を洗い出す |
| **反証** | 「本当にそうか」を問い、反対の証拠や代替案を提示する |
| **証拠追加** | 事実確認に必要な根拠・出典・具体例を補足する |
| **長期リスク発見** | 数週間後・数ヶ月後に問題になる可能性を指摘する |

---

## レビュー後のフロー

```
提案 → レビュー → 重大指摘あり？
                    ├─ Yes → 修正 → 必要と判断した場合のみ再レビュー
                    └─ No  → Decision OSへ
```

### ルール

1. **重大指摘があれば修正する**（設計のひっくり返しではなく、指摘箇所の修正）
2. **再レビューは必要と判断した場合のみ**（全件再レビューはしない）
3. **レビュー担当AIは固定しない**（固定すると盲点が固定される）
4. **複数AIレビューを推奨する**（Grok、ChatGPT、Claude、Perplexity等を組み合わせる）

---

## レビュー出力フォーマット

```
## レビュー結果

- **レビュー担当**: （AI名 or 人間）
- **重大指摘**: あり / なし
- **指摘内容**: （箇条書き）
- **推奨対応**: （修正内容の提案。採用判断はしない）
- **再レビュー要否**: 要 / 不要
```

---

## レビューでやらないこと

- 採用・保留・却下の判定（→ Decision OS）
- 新しい機能・仕組みの提案（→ Proposal Policy違反）
- ユーザーへの寄り添い型の一般論（→ 設計を膨らませる原因）

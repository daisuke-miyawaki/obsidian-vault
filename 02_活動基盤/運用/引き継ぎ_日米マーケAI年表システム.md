## 4. Cursor（前チャット）の回答・推奨案

### 4-1. 結論：仮フローは v0 には使えるが、2ヶ月更新には不向き

| 宮脇さんの仮説 | 問題点 | 推奨 |
|----------------|--------|------|
| NotebookLMでレポート生成 | 文章は得意、**JSON等の構造化データが苦手** | リサーチ用◎。最終出力はJSONスキーマ付きプロンプトで別AIへ |
| CursorでHTMLを毎回書き直し | **デザイン崩れ・枠消費** | 初回だけ。更新はJSON差し替えのみ |
| 2ヶ月ごとにCursor | コスト最小化の目的に反する | **更新時Cursor不要**にする |

### 4-2. 推奨パイプライン（3段）

```
【初回のみ・Cursor 1セッション】
  JSONスキーマ + index.html + style.css + render.js + 更新用プロンプト雛形

【2ヶ月ごと・外部AI（無料枠）】
  Step1: NotebookLM Deep Research … Vault知識＋日米差の深掘り
  Step2: Grok / Perplexity … 最新トレンド・X上の話題検知
  Step3: Gemini等 … Step1+2を入力し、JSONスキーマに沿った data.json を1発出力

【2ヶ月ごと・手作業ゼロ】
  data/timeline-latest.json を差し替え → ブラウザを開く → 完了（Cursor不要）
```

### 4-3. ツール役割分担（Cursor案）

| ツール | 役割 |
|--------|------|
| **NotebookLM** | 既存ナレッジ統合（発信戦略メモ・商品ライフサイクル・OS・03_素材庫） |
| **Grok / Perplexity** | 未知の最新トレンド検知 |
| **Gemini（無料）** | JSON整形（スキーマ強制） |
| **Cursor** | 初回土台＋年1回程度のスキーマ拡張時のみ |

※ [0900_AI戦略](01_人生戦略OS/0900_AI戦略.md)と同じ思想：重い作業は外部ツール、Cursorは設計と初回構築。

### 4-4. 土台設計の鉄則

**中身は全部JSON、見た目は全部CSS＋JS**

```
timeline-system/          （置き場所は未決・宮脇さんOK後）
├── data/
│   ├── timeline-2026-07.json   … スナップショット（履歴）
│   └── timeline-latest.json      … 常に最新（これだけ2ヶ月ごとに差し替え）
├── schema/
│   └── timeline.schema.json      … 外部AIへの出力指定＋検証用
├── prompts/
│   └── bi-monthly-update.md      … 2ヶ月更新用プロンプト（コピペ用）
├── index.html                    … 殻だけ。中身を書かない
├── style.css                     … フェーズごとの色・帯の見た目
└── render.js                     … JSONを読んで帯を描画
```

**4カテゴリ（Cursor案・要確認）：**
1. `marketing_method` … LP・サブスク・会員等の手法
2. `media_channel` … note・ショート・ポッドキャスト・YouTube
3. `ai_tool` … Cursor・Dify・AIエージェント・RAG・音声クローン
4. `adoption` … 日米の採用タイミング（誰がいつ使い始めるか）

**4ステージ（Cursor案・帯の色で表現・要確認）：**
1. `emerging` … これから（黎明・話題になる）
2. `growing` … 伸びる（入るべき時）
3. `peak` … ピーク（盛り上がり・飽和手前）
4. `declining` … 落ちる・次の形へ

**各アイテムのデータ（Cursor案）：**
- レーン：`US` / `JP` / `JP-Nagoya`（3本）
- 帯：`start` / `end`（年月）→ 長さと位置を自動計算
- `note` … 生活習慣の考察（車社会vs電車、名古屋の地方都市リアル）
- `action` … 宮脇さん向け判定（入る / 維持 / 縮小 / やめる）

**デザインを崩さない仕組み：**
- HTMLは `<div id="timeline"></div>` 程度の殻
- render.js が JSON から帯を動的生成
- 更新＝JSONの数値とテキストだけ変更 → CSS/JSのルールは不変

- 米国比2〜3年遅れが多い（Gartner Japan分析）
- 宮脇さんの顧客層はさらに遅れる → 提案チャンスのずれが生まれる

**ほぼない。** 部品は豊富（Gartner、MBA商品ライフサイクル、Rogers普及曲線、発信戦略メモ）。**宮脇さん用に統合して作る**のが現実的。

## 1. 最重要：この相談の前提とスタンス
このプロジェクトの目的を達成するために、あなた（Cursor）と**「相談しながら、最適な進め方をゼロベースで決めていきたい」**と考えています。

## 2. 達成したい「目的」
今（2026）から今後2〜3年後までの間に、日本およびアメリカで登場・変化する「主要なマーケティング手法」と「AIツール・考え方」のライフサイクルを可視化する「世界史年表風のビジュアル（4カテゴリ×4ステージ）」を作りたい。

このシステムにおいて、以下の条件をすべて満たすことがゴールです。
* **ユーザー（私）の手作業はゼロ：** 2ヶ月ごとの更新時、私がカーソルを動かして図を作るような作業は一切せず、AIが自動でビジュアル（帯の長さ、位置、考察テキスト）を上書き更新する。
* **Cursorの消費枠（コスト）の最小化：** あなた（Cursor）に重いリサーチや試行錯誤をさせて枠を無駄遣いしたくない。時短・低コストで最大の成果を出したい。
* **世の中の未知のトレンドとリアルな考察の網羅：** 私の知らない最新トレンドを検知し、「車社会のアメリカ vs 電車社会の日本（さらに名古屋のような地方都市のリアル）」といった、生活習慣に踏み込んだ精度の高い考察（予備情報）が組み込まれていること。

## 3. 現時点で考えている仮のフロー（たたき台）
現在は、以下のように「外部の無料ツール等に重労働をさせ、Cursorには最後の美味しいところ（出力）だけをやらせる」のが一番コストが低いと考えています。

1. **【リサーチ・分析】**

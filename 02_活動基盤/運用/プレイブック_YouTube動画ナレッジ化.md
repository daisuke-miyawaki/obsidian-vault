# プレイブック：YouTube動画ナレッジ化

## 目的

YouTube動画をMarkdownナレッジに変換する。かくじかん38本で確立した手順の決定版。

**新チャットでも [[作業ログ_YouTubeナレッジ化]] と本ファイルを読めば再現できる。**

---

## なぜNotebookLMか（重要）

Cursorだけで動画を処理する「力業」は避ける。

| 方法 | 問題 |
|------|------|
| Cursor力業 | AI枠・コスト・時間が大きい |
| **NotebookLM＋スクリプト** | 無料枠活用、Playwrightが自動操作、再現性高い |

この方針はユーザー（宮脇）が提案。コストと労力の両方を抑える。

## 2つのモード（A / B）

| モード | いつ使う | URLファイル | コマンド |
|--------|----------|-------------|----------|
| **A: チャンネル全本** | チャンネル全体を資産化（初回向け） | `_urls_all.txt` | `add-sources` → `run-all` |
| **B: 個別動画だけ** | **次回以降の基本**。必要な動画だけ | `_urls_selected.txt`（ユーザーが選んだURL） | `run-one 001` または選んだ分を順に処理 |

### モードBの手順

1. ユーザーからURL（1本〜数本）を受け取る
2. チャンネルフォルダに `_urls_selected.txt` を作る（形式：`タイトル|URL`、1行1動画）
3. `config.yaml` の `paths.urls_file` を `_urls_selected.txt` に一時変更
4. `./run.sh run-one 001` で1本試作 → OKなら残りを処理
5. 完了後、必要なら `urls_file` を `_urls_all.txt` に戻す

**モードBのりんご渡し：**

> 「この動画をナレッジ化して。URLは{URL}。かくじかんと同じ形式で。」

### モードAの手順（かくじかん実績）

1. `yt-dlp` でチャンネル全動画のURL一覧を `_urls_all.txt` に出力
2. `add-sources` → `run-one 001`（試作）→ `run-all`（残り全本）

## 失敗と回避（かくじかんで学んだこと）

| 症状 | 対処 |
|------|------|
| 「ソースを追加」が見つからない | `notebook_url.txt` がホームURLのままだった（かくじかん001で発生）。空にして再実行、またはスクリプト修正済み版を使う |
| UIが変わって動かない | `src/selectors.py` のセレクタを更新 |
| 途中で止まった | `state/progress.json` から再開可能 |
| 失敗時の画面 | `state/screenshots/` を確認 |
| 再ログイン | `python -m src.main login` |
| **途中の番号（例012）で毎回止まる** | **チャット履歴が溜まっている**可能性大。スクリプトは質問前に履歴削除するよう修正済み（2026-06-30） |
| 「答えられません」がすぐ出る | 長いプロンプト＋履歴の組み合わせ。履歴削除後に再試行 |
| 「1日の上限に達しました」 | **その日は続行不可**。翌日まで待つかNotebookLMをアップグレード |
| 15分以上無反応 | 上限・拒否の可能性。`response_timeout.png` を確認（待つだけでは直らない） |
| 既存ブラウザセッションで開けない | 裏のChromeが残存。プロセス終了後に `./run.sh run-one 00X` を**1本ずつ**実行（`for`一括禁止） |

### 複数本処理するときの鉄則（isaで学んだこと）

- **10本前後ごと**にチャット履歴が原因で拒否されやすい → 1本ごとに履歴削除（自動化済み）
- **1日のチャット上限**がある → 失敗を繰り返さない（即停止して翌日へ）
- **再開は `run-one` を1本ずつ**。`run-all` や `for` ループはブラウザが壊れやすい

## 1. 2026年の検索環境

### 1-1. 変わっていないこと

Googleの目的は「ユーザーが求める答えに届くこと」。

### 1-2. 変わったこと

- AIで一般論・まとめが量産 → **Helpful Content・E-E-A-T・Experience** がより重要
- **AI Overview / AI Mode** … 要約内に引用される。クリックは減りうるが、**引用＝新しい価値**になる
- **GEO（Generative Engine Optimization）** … ChatGPT、Perplexity、Google AI 等に**引用される**ための最適化。従来SEOと並行が必須
- 目標は **Ranking（順位）** だけでなく **Recognition（認識）** … AIの会話の中でブランド・主体が推奨・言及されること

### 1-3. SEOとGEOの違い（要点）

| | 従来SEO | GEO |
|--|---------|-----|
| 狙い | 検索結果のリンククリック | 生成回答への**引用** |
| 評価単位 | ページ全体の順位 | **パッセージ（文章の断片）** |
| 強い信号 | 被リンク、技術SEO、キーワード | ファクト密度、抽出しやすい構造、鮮度、エンティティ（主体）の明確さ |
| 効果の目安 | 3〜6ヶ月 | 引用は4〜8週で動き出すことも（サイトによる） |

### 1-4. 2026年の結論

> **「独自性 × 位置情報 × 一次情報」を、ゆらぎ・段階公開で積み上げる。公開前の人間確認は品質のため（Googleは下書き工程を見ない）。**

## 2. 評価の4本柱

### 柱① 独自性

- 自社・本人・現場にしかない数字、写真、工程、判断、失敗、直し方
- 一般スペック説明＋**自社データ**が最低ライン

### 柱② 位置情報・文脈

- ローカル：市区町村、サービスエリア、GBPとの一致
- 全国向けでも業種・現場・条件の文脈を書く

### 柱③ 一次情報・E-E-A-T

| 要素 | SEOでの具体 |
|------|-------------|
| Experience | 日報、作業ログ、Before/After |
| Expertise | 資格、年数、判断の理由 |
| Authoritativeness | 継続更新、被リンク、メディア言及 |
| Trust | 誇大なし、運営者情報、透明性 |

**ファクト密度（GEOでも重要）：** 100語程度ごとに、検証可能な**数字・固有名詞・日付**を入れる。AI引用・信頼の両方に効く。

### 柱④ 信頼の一貫性

- 理念・約束・実際の運営が記事と矛盾しない（言行一致）
- 応援される理由をプロセスで見せる

## 3. 絶対に避けること

| 禁止 | 理由 |
|------|------|
| ミラーサイト・大量複製 | 低品質・重複 |
| 一括大量公開 | ボット的パターン |
| AIだけの一般論 | Helpful Content 違反 |
| ゆらぎだけで中身がない | 空っぽの言い換え |
| 均一すぎるAI文体の連続 | スパム指標になりうる |
| **`nosnippet` の乱用** | AI引用がスニペット依存のため可視性を下げうる（§9） |
| **LLMs.txt に依存** | 引用効果の実証は弱い。優先度は低い |

## 4. サイト・コンテンツ設計

### 4-1. 基本原則

1. **1ページ1検索意図**
2. **トピッククラスター** … 1キーワードだけでなく、関連するサブ質問群を網羅（AIはクエリを分解して収集する）
3. **ロングテールの網** … 中身付きでページを増やす
4. **内部リンク** … クラスター内・エリア↔詳細を意味あるアンカーで
5. **鮮度** … AI引用コンテンツは相対的に新しいものが選ばれやすい。重要ページは定期更新・更新日を明示
6. **積み上げ** … 古い一次情報も資産

### 4-2. AI引用・GEO向けの書き方

**First 200 Words Rule（冒頭200語ルール）**

- ページ上部（おおよそ最初の30%）で、**主要な問いに直接答える**
- 各H2セクションの**冒頭1〜2文**も、その見出しの結論を先に書く
- AIは「ページ全体」より**パッセージ**を引用する。自己完結した短い段落を意識する

**構造**

- FAQスキーマ、見出し階層、箇条書き … **抽出しやすい**構造
- 統計・出典・日付を明記
- ペイウォール・クロールブロックの背後に核心を置かない

### 4-3. ページの型（業種共通）

| 型 | 目的 |
|----|------|
| サービス・商品詳細 | 成約。1件1ページ＋固有データ |
| エリアLP | ローカル `[地域]×[サービス]` |
| 工程・こだわり固定ページ | E-E-A-T |
| 実績・メディア | Trust |
| 日報・ログ | Experience・鮮度 |
| FAQ・知識 | 検索意図＋独自見解必須 |
| ハブ（クラスター親） | 関連トピックへの内部リンク集約 |

### 4-4. 記事の型

**型A：現場ログ** … 事実／判断／次／文脈  
**型B：問題→試行→気づき**  
**型C：段階・自己診断**（現在地・罠・処方）  
**型D：専門×文脈**

## 5. 人工的ゆらぎ（必須）

### 5-1. 定義

大量生成時に**機械的同一パターンを意図的に崩す**処理。  
**中身の代替ではない。** 独自性の上に載せる。

### 5-2. なぜ必要か

Googleは公開の足跡（一括公開、同一構文、規則的更新）も見る。

### 5-3. 手法（ページごと）

| 手法 | 内容 |
|------|------|
| 文字数ゆらぎ | 目標±10〜20% |
| 見出し順 | H2/H3ブロックの入れ替え |
| 句読点・段落 | 一定確率で変化（可読性下限を守る） |
| 表記 | 漢字／ひらがなの統一ルールをページごとに |
| 文末 | 「です／となっています／特徴があります」等 |
| 語順 | 意味を変えない言い換え |

**禁止：** 事実捏造、読めない乱れ、スピンだけ

### 5-4. セット必須3技術

1. **段階的生成** … 一度に長文を書かせない（§6）
2. **独自データのハイブリッド** … CSV・実績数・地域・日付をプロンプトへ
3. **タイマー分散公開** … 1日5〜10件など予約。一括公開しない

### 5-5. 判断フロー

```
一次情報あり？
  NO → 中身を先に作る
  YES → 大量生成必要？
    NO → 手動 or 少量で可
    YES → 段階生成 + 独自データ + ゆらぎ + 分散公開 + 下書き確認
```

## 6. 段階的AI生成

### 6-1. パイプライン

```
[元データ] CSV / メモ / マスタ
    ↓
[抽出] 固有フィールド → プロンプト
    ↓
[分割生成] テーマ1〜4を個別生成
    ↓
[結合] 重複削除
    ↓
[ゆらぎ] §5-3
    ↓
[下書き保存] CMS・note等（公開しない）
    ↓
[人間が閲覧・修正] §7-2 ← 必須
    ↓
[予約公開] 分散タイマー
```

### 6-2. 分割テーマ例

1. 特徴・需要  
2. 利用シーン・市場  
3. 利用者メリット・注意点  
4. **主体固有データ**（実績、地域、工程）

### 6-3. 品質ゲート（機械＋人間）

- 固有名詞・数字のファクトチェック
- 繰り返し段落の検出
- 冒頭200語で問いに答えているか
- 画像・alt・内部リンク

## 7. 人間×AIの役割

### 7-1. 役割分担

| 工程 | 人間 | AI |
|------|------|-----|
| ネタ・事実・現場 | ◎ | × |
| 分割・ルール設計 | ◎ | 補助 |
| 下書き生成 | — | ◎ |
| **下書き閲覧・修正** | **◎ 必須** | × |
| **公開ボタン** | **◎ 必須** | × |
| ゆらぎ・予約 | ルール設計 | ◎ 実行 |
| 媒体別変換 | 選別 | ◎ |

**原則：** メモが原石。加工なし公開はしない。AIは増幅装置。

### 7-2. 下書き確認（品質管理・必須）

**位置づけ：これはSEOの「Google向けテクニック」ではなく、品質チェックである。**

- Googleのクローラーは **WordPressの下書き・管理画面・社内の承認ログは見ない**
- Googleが間接的に見るのは **公開されたページの中身** と **公開のパターン**（一括公開の規則性、タイムスタンプ等）のみ
- 人が下書きを読む理由：誤情報・ハルシネーション・トーンのズレを防ぎ、**公開後の品質**を上げるため

自動生成した記事は、**必ず一度「公開前の状態」で人間が読んでから**出す。

**手順：**

1. CMS（WordPress等）または note の**下書き**に保存（この時点ではインデックスされない）
2. **プレビュー**または管理画面で、読者と同じ見え方で確認
3. 事実・数字・固有名詞・トーンを修正
4. 問題なければ**人間が公開**（または予約公開）

**やってはいけないこと：**

- AI出力をそのまま自動公開
- 「Googleが下書き確認を評価する」と誤解して運用する（そういう仕組みはない）

**Google向けに効くのは別：** 分散予約公開（§5-4）、ゆらぎ、一次情報の中身など、**公開後に見える要素**である。

### 7-3. 自動化の理想形

1. フォルダに短いメモ（3行〜）  
2. 監視→AI変換→ゆらぎ→**下書き**  
3. 人間が閲覧・承認  
4. 予約公開

## 8. GEO（生成エンジン最適化）

### 8-1. 目的

Google AI Overview、AI Mode、ChatGPT、Perplexity 等の**回答に引用される**こと。

### 8-2. 引用されやすいコンテンツ

- 冒頭で直接回答（§4-2）
- ファクト密度（数字・日付・固有名詞）
- 一次情報・Experience
- 抽出しやすい構造（見出し、FAQ、箇条書き）
- **鮮度**（更新日、定期的な見直し）
- ペイウォール・クロールブロック外に核心を置く

### 8-3. Recognition（認識）

順位だけでなく、**ウェブ全体でのブランド言及**も効く。

- 業界メディア、レビュー、ポッドキャスト、フォーラム等での文脈ある言及
- 特定トピックとブランドが結びつく**トピックオーソリティ**
- 運営者・会社・著者の**エンティティ**をAboutページ、構造化データで明確化

※ 無理な外部リンク購入は禁止。一次情報発信と正当なPRが正道。

### 8-4. ゆらぎとGEO

ゆらぎは**Googleのスパム回避**と**読者への自然さ**のため。  
GEOの本体は **中身（一次情報）＋構造（抽出可能性）＋鮮度** である。

## 9. 技術SEO

| 項目 | 要点 |
|------|------|
| インデックス | 低品質ページを増やさない。noindex判断 |
| サイトマップ | 公開URLを正確に |
| 表示速度 | 画像圧縮、モバイル優先 |
| 構造化データ | LocalBusiness、Product、FAQ（虚偽禁止） |
| canonical | 重複URL正規化 |
| 内部リンク | 孤児ページを作らない |
| **クロール可能性** | robots.txt、ステータスコード、主要ページがブロックされていないか定期監査 |
| **`nosnippet`** | AI引用を狙うページでは乱用しない |
| **LLMs.txt** | 必須ではない。優先度低 |

## 11. 運用・測定

### 11-1. 最小ルーティン

| 頻度 | やること |
|------|----------|
| 毎日 | 現場メモ1件 |
| 週次 | メモ→下書き→**人間確認**→公開 or 予約 |
| 月次 | Search Console（通常＋**AIパフォーマンス**）、エリア穴チェック |
| 四半期 | 低品質ページ整理、内部リンク見直し、鮮度更新 |

### 11-2. Search Console（2026年）

**Search Generative AI パフォーマンスレポート**（2026年6月〜）を確認する。

- どのURLが AI Overview / AI Mode に**表示（インプレッション）**されたか
- クリック数は出ないが、**AIが評価しているページ**の特定に使える
- 引用されやすい構造・トピックの分析に活かす

### 11-3. 効果の目安

| 成果 | 目安 |
|------|------|
| インデックス・表示の兆し | 1〜3ヶ月 |
| AI引用・GEOの兆し | 1〜2ヶ月〜（サイトによる） |
| ニッチ・地域KW流入 | 3〜6ヶ月 |
| ドメイン評価向上 | 6〜12ヶ月 |
| 問い合わせ・信頼 | 6〜18ヶ月 |

## 12. 公開前チェックリスト

### 内容
- [ ] 独自性（他にない情報）
- [ ] 位置情報・文脈
- [ ] 一次情報・Experience
- [ ] AI一般論だけではない
- [ ] 検索意図に答えている
- [ ] **冒頭200語で核心に触れている**
- [ ] 数字・日付・固有名詞（ファクト密度）

### 量産・AI生成
- [ ] 段階的生成
- [ ] 固有データをプロンプトに入れた
- [ ] ゆらぎ適用
- [ ] 分散予約（一括公開していない）
- [ ] **下書きを人間がプレビューで確認した**（品質管理。Googleは下書きを見ない）

- [ ] 誇大・虚偽なし
- [ ] 運営者情報明確
- [ ] 理念と矛盾なし

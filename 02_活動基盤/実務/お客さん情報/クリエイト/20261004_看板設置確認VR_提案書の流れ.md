# 看板設置確認VR｜提案書の流れ

このメモは、**提案書の本文そのものではない。** 先に決める「誰に何の順で話すか」である。この順で提案書を書き、同じ順で動画にする。

## 誰に出すか（混ぜない）

| 相手 | この資料の役割 |
|------|----------------|
| クリエイト（波多野さん） | 工務店・施主に説明するときの台本。提案書 → 動画 |
| 工務店・施主 | 動画と、その下のサンプルで「現場の見え方」を自分で触る |
| 宮脇のホームページ閲覧者 | 同じページで、説明のあと実際に操作できることを見る |

工務店向けの話と、宮脇がクリエイトへ出す見積の話は、同じ「安い」という言葉にしない。後述の「金額の二層」を守る。

## 全体の順（提案書＝動画）

ユーザー指定の骨格はこれでよい。

1. 現場でいま起きている問題を並べる  
2. この仕組みで、その問題がどう消えるかを一対一で返す  
3. 画面（スクリーンショット）と、いま操作できること  
4. そのあとで金額（従来は高かった／AIでここまで出せる）  
5. 次の一手（URLを渡す、波多野さん確認のあと工務店が同じ空間を見る）

金額を画面の前に出さない。先に「何が見えて、何が直せるか」を見せる。

## 提案書の目次

各節は、提案書1枚〜数枚、動画ではおおむねその秒数目安。尺は仮。書き始めてから詰める。

### 0. 表紙・一言（提案書1枚／動画 0:00–0:20）

**言うこと**

- 題名案：**建っている現場の看板を、ブラウザで確認する**
- 対象は「もう壁がある現場」に付ける看板。空き地に家を立てる話は出さない
- 見るものはアプリ不要。URLを開けば PC・スマホ・Quest で同じ空間

**出さないこと**

- ネオン管、紙の実物大、4m超の工作物申請、構造計算、公図

### 1. いま現場で起きていること（問題の羅列）（提案書2〜3枚／動画 0:20–1:20）

2026-09-16 MTG と翌日方針から、工務店・施主の口に乗る言葉だけを並べる。社内の Illustrator 不具合や構造計算外注は、この節に入れない。

| # | 現場・確認で起きていること | 出典の意味 |
|---|---------------------------|------------|
| 1 | 図面と看板単体のイメージ図では、建物の全景の中でどう見えるかが伝わらない | 提案 2.1 |
| 2 | 建築CGパースはアングルが固定で、直すたびに手間が大きい | 提案 2.2 |
| 3 | 大判モック・模型は制作の金と時間が大きく、小規模案件に向かない | 提案 2.2 |
| 4 | 全景が初めて揃うのが、現場立ち合い・墨出し・足場ばらし前になりやすい | 従来手順 |
| 5 | 施主が事務所に来ないと、家族と一緒に見られない。検討が伸びる | 提案 3.3 |
| 6 | 位置の合意が「だいたいここ」で終わり、製作に渡す数字（壁の上から何mm、右から何mm）が残らない | 方針 §2 |
| 7 | 通信が弱い現場でも、紙だけだと全景の確認ができない | テザリングでURL、という前提 |

提案書では、各行を短い文で書く。動画では1〜4を必ず言い、5〜7は時間があれば足す。

**設計士と施工が平行線になる話**は、別ナレッジ（AI現場監督）側。このVRの直後に出さない。09-16訂正どおり、この提案の本線ではない。

### 2. こう解決する（問題と一対一）（提案書2〜3枚／動画 1:20–2:20）

表にする。左が問題、右がこのシステムの返し。抽象的な「DX」は書かない。

| 問題 | 返し |
|------|------|
| 全景の中の見え方が分からない | 建物と看板を一つの空間で見る。360度回せる |
| パースのアングル固定・修正が重い | ブラウザ上で位置・大きさ・ロゴをその場で切り替える |
| モックが高すぎる | 実物大の板を先に作らず、同じ確認をURLで先に済ませる |
| 立ち合いまで全景が揃わない | 製作前に波多野さんが先に見て、OKのあと工務店が同じURLを開く |
| 家族と一緒に見られない | インストール不要。LINE・メールでURL |
| 数字が残らない | 画面保存に加え、壁からのmm一覧を残す |
| 現場の通信 | スマホのテザリングで同じURLを開く |

人の流れ（本番。提案書に番号で書く）

1. 建物の正面写真または JW、現場写真、周辺の地図スクショ、看板の `.ai` を入れる  
2. プログラム／AIが建物と看板の立体を作り、壁に置く  
3. 人が位置・大きさ・色・ロゴを直す  
4. 画面と数値を保存する  
5. URLを渡す。**波多野さんが先に見て、OKのあと工務店が同じ空間を見る**

### 3. 実際の画面と、いま操作できること（提案書の核／動画 2:20–4:00）

**金額の前に、必ずこの節を置く。**

#### 3.1 見せる画面（スクリーンショット）

最低4枚。提案書に貼り、動画では同じ順で操作する。

1. 昼の全景（建物＋看板。新知工業サンプル）  
2. 夜＋バックライト点灯  
3. ロゴ切替（A／B／C の差が分かるアングル）  
4. サイズ 70% と 130% の比較（100% を基準に）  
5. （任意）取付位置の数値（正面右上＝0,0、cm）を動かしたあと  

注記を画面のすぐ下に書く：**これは新知工業社屋のサンプルである。お客さんの現場そのものではない。**

#### 3.2 いまサンプルで操作できること（2026-10 公開ビューア）

公開URL（宮脇サイト uploads）:

`https://sunnysh.net/wp-content/uploads/3d/kogyo-3d-viewer.html`

| 操作 | 内容 | 第1本の目標との差 |
|------|------|-------------------|
| 時間帯 | 昼／夜 | 一致 |
| バックライト | 点灯／消灯 | 一致 |
| ロゴ | A 横一列／B 下線入り／C 2段 | 目標は5種。サンプルは3種 |
| サイズ | 70%／100%／130%（表示例 W 5.80 m × H 0.85 m） | 一致。無段階ゲージは出さない |
| 取付位置 | 正面右上＝0,0 からの cm 入力 | 目標の「保存してmm一覧」までは未完了 |
| VR | ブラウザのまま（WebXR）。Quest は Enter VR | 第1本の Quest は宮脇所持 |

提案書に「5種ロゴ」「全色」と書かない。サンプルで嘘になる。色は「この案件で使う色の周辺だけ」と書く。

#### 3.3 色について（短い免責）

画面は全景の形と寸法の確認用。色・質感の最終判断はカットサンプル。CGと実物は光でずれる。09-16以降の提案第7節と同じ。

### 4. 金額（従来は高かった／AIで出せる）（提案書2枚／動画 4:00–4:50）

#### 金額の二層（ここを混ぜると提案が壊れる）

| 層 | 誰の話か | 言ってよいこと | いま書いてはいけないこと |
|----|----------|-----------------|---------------------------|
| A. 確認手段 | 工務店・施主 | 大判モック・模型は金と時間が大きい。CGパースは直すたびに手間。Web3Dは小〜中規模（2〜3階・店舗）でコスパが最も高い | 1件あたり「このVRは○万円」と仮置きしない（未決） |
| B. 仕組みの作り方 | クリエイト社内、および宮脇HPの「なぜ今できるか」 | 従来、外部のシステム会社に出すと**数百万円・数ヶ月**になりがちだった確認用の仕組みを、AI（内製）で**数日〜数週間**で形にしている | 構造計算外注 3.5万〜5万円／件を、このVRの値段の根拠にしない（別レーン） |

工務店向け動画では、層Aを先に言い、層Bは「だから今回、この確認を案件に載せられる」の一文で足りる。  
宮脇HPでは層Bを少し厚くしてよい。同じ「安い」で工務店の工事代金が下がったように聞こえない言い方にする。

**提案書に円を書くときは、宮脇が数字を決めてから。** 方針上、金額・見積・無償修正回数は宮脇が決める。2026-09-27時点で未記入。

### 5. 使い方と次の一手（提案書1枚／動画 4:50–5:30）

## ホームページへの置き方

置く場所：宮脇のホームページ（現状の実体は `sunnysh.net`）。クリエイトのXserver公開ページは、このメモの時点では本線ではない。

上から下の順：

1. **見出し** … 看板設置確認VR（サンプル：新知工業社屋）  
2. **説明動画** … 上の流れ。埋め込み（YouTube非公開または直mp4は後で決める）  
3. **操作できること** … 3.2の表を3〜5行に短縮  
4. **実機サンプル** … iframe。高さは画面の八割程度  

iframe の `src` は **`/wp-content/uploads/3d/kogyo-3d-viewer.html`** にする。キット説明の `index.html` はサーバー上 404 のままなので、そちらを指すと真っ白になる。

```html
<iframe
  src="/wp-content/uploads/3d/kogyo-3d-viewer.html"
  style="width:100%;height:80vh;border:0;"
  allow="xr-spatial-tracking; fullscreen"
  title="新知工業 看板設置確認サンプル">
</iframe>
```

5. **注記** … サンプル案件であること。色の免責。`noindex` の直URLを検索流入の本線にしないなら、固定ページ側でインデックス方針を決める  

固定ページ `/kogyo-3d/` は未公開。動画ページを先に作り、その下に iframe を置く方が、ユーザーの指定（動画の下にサンプル）と一致する。
